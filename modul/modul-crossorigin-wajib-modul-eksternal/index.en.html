Require crossorigin on Clincoo Modules Imported from Another Origin

A module from a CDN or another domain fails without crossorigin. The browser rejects a cross-origin import that is not CORS.

Artikel ini tersedia dalam: English · Indonesia

On editor.clincoo.buzz, a script type=module whose src points at a CDN often stays silent in the console: failed to fetch dynamically imported module.

Add the crossorigin attribute on the module tag. The CDN must send a matching Access-Control-Allow-Origin. Without that header, the import still fails even if the URL is correct.

Do not mix a same-origin module with a CDN import that does not send CORS. One failure in the import graph stops the whole entry file.

Ask AI to mark every cross-origin import and add crossorigin only on that tag. Refuse moving the whole app onto a CDN.

Test in the app.clincoo.buzz preview with the Network tab. A 200 without a CORS header still fails for a module.
