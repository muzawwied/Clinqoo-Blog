Export Functions from Clincoo Modules, Do Not Run Side Effects on Import

Top-level module code runs as soon as it is imported. That fires network calls or changes the DOM before the page is ready.

Artikel ini tersedia dalam: English · Indonesia

Clincoo snippets often call fetch or querySelector outside a function. Importing that file from another page runs the same effect.

Wrap the work in export function init(). Call init from one entry point after the element exists. A module may export constants, not mutate the page immediately.

The only side effects allowed at top level are pure definitions. Do not attach a global listener outside init, because hot reload and preview will attach it twice.

Ask AI to move fetch inside init and return a list of leftover side effects. Refuse hiding errors with an empty catch.

Test importing the module from a blank page on editor.clincoo.buzz. There should be no network request before init is called on app.clincoo.buzz.
