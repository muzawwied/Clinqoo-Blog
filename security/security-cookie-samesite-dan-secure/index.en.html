Set Clincoo Cookies with SameSite and Secure

A session cookie without SameSite and Secure rides along on cross-site requests. Set the attributes where the cookie is created.

This article is available in: Indonesia · English

A login or preference form on app.clincoo.buzz sometimes writes document.cookie with no attributes. Older browsers send that cookie on third-party requests.

If the cookie must exist, set Secure and SameSite=Lax for a normal session, or Strict if it should not follow navigation from other sites. Add HttpOnly only when the server sets the cookie, not JS.

Do not store an API token in a cookie page script can read. Keep only display preferences on the client.

Test in Application, Cookies panel, after preview. Secure and SameSite must be set. Ask the AI to review one set-cookie line, not the whole auth flow.

Cookie attributes do not replace server checks. They cut requests you did not intend.
