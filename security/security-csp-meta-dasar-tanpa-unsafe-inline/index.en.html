Add a Basic CSP Meta without unsafe-inline on Clincoo

Content-Security-Policy holds back foreign scripts. Start strict, then allow only domains you actually use.

This article is available in: Indonesia · English

Pages from editor.clincoo.buzz often load one analytics script plus an embed. Without CSP the browser accepts a script from any domain that lands in the HTML.

Add a Content-Security-Policy meta in the head: default-src self, script-src self, style-src self unsafe-inline only while inline CSS remains, img-src self data https. Avoid script-src unsafe-inline unless there is no other path.

Test in the Chrome DevTools Console tab. CSP violations show as clear errors. Paste that message into the assistant on app.clincoo.buzz with the head snippet.

If a third-party widget breaks, allow that domain one by one — do not go back to a wildcard. Redeploy to blog.clincoo.buzz after the meta is stable.
