Retry Temporary Failed Clincoo Fetches, with a Hard Limit

A 429 or a brief network drop is not a reason for an endless loop. Cap retries at 2–3 and show a message.

This article is available in: Indonesia · English

Fetches to a form API or article list sometimes fail because the network flickered or the server rejected a burst. One or two retries are reasonable. Unlimited retries freeze the button and pile up requests.

Tell errors apart. Do not retry 400 or 401: bad input or auth will not heal. 429, 503, or a network TypeError may be retried after a short delay.

Use AbortController so an old attempt cannot overwrite a new one. Disable Submit during the retry sequence. Show “retrying…” then a failure message when the cap is reached.

In the Clincoo preview, test with the Network tab set Offline then Online. Visitors should see status, not a raw console error. Never store API keys in page JavaScript.

Log status codes on your own endpoint if you have one. Without status, the team blames CSS when the API actually refused the request.
