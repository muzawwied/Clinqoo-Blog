Do not show a server stack to users, keep it in the log

A raw exception leaks paths and queries. Show a short code, and keep the stack in an internal log.

This article is available in: Indonesia · English

A failed Clincoo API response sometimes returns a full stack. That helps in a local console and hurts on a public page.

Map status 500 to a fixed sentence plus a reference code. Do not render the raw body into the DOM.

In Network, copy the request id, not the whole error HTML. Send that id when you ask for help in editor.clincoo.buzz.

Ask AI to design an error-code map. Refuse a suggestion that prints process.env or a server path.

Test an app.clincoo.buzz endpoint with a broken body. The UI shows only could not process and a code. The stack stays in the log.
