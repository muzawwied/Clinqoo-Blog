Handle Offline and Network Failures in Clincoo Fetch Calls

A fetch that fails offline often surfaces as a raw JS error. Show a message and a retry button.

This article is available in: Indonesian · English

In Clincoo preview a contact form that calls an API looks fine on stable Wi-Fi. In the field a visitor can lose the network the moment they press send.

Wrap fetch in try/catch. Network failures throw TypeError, not an HTTP response. Do not treat that as a 500 status.

Use navigator.onLine as an early hint, but still handle fetch errors: onLine can be true when DNS fails.

Show a short message near the button: you are offline, try again. Do not clear the form the user already typed.

Disable the submit button while the request runs, then enable it again on failure. Avoid a queue of duplicate fetches from repeated clicks.

Test with DevTools offline mode before release. Ask AI to add a network-error branch, then verify the copy matches the page language.
