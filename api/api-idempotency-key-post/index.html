Kirim Idempotency-Key pada POST Formulir Clincoo

Koneksi putus setelah kirim form bisa menduplikasi pesanan. Idempotency-Key membuat ulang permintaan aman.

Artikel ini tersedia dalam: Indonesia · English

Menonaktifkan tombol Kirim membantu, tetapi tidak cukup. Pengunjung bisa refresh, service worker bisa mengulang fetch, atau timeout memicu percobaan kedua. Tanpa kunci unik, server melihat dua POST yang sah.

Sebelum fetch, buat satu token (UUID) dan simpan di sessionStorage bersama status formulir. Kirim token di header Idempotency-Key atau field tersembunyi. Backend yang mendukung akan mengembalikan respons pertama jika kunci yang sama datang lagi.

Jangan daur ulang kunci antar pengiriman berbeda. Setelah respons 2xx, hapus token dan buat yang baru untuk pengiriman berikutnya. Untuk 5xx atau jaringan putus, pakai kunci yang sama saat retry — itu intinya.

Jika API pihak ketiga tidak menerima header itu, tetap kirim clientRequestId di JSON. Catat id di log Clincoo agar tiket dukungan bisa menelusuri pesanan ganda.

Uji di tab Network: kirim sekali, lalu ulangi fetch yang sama. Yang benar adalah satu catatan di server, dua respons identik di klien.
