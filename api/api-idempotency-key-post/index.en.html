Send an Idempotency-Key on Clincoo Form POSTs

A dropped connection after submit can duplicate an order. An Idempotency-Key makes retries safe.

This article is available in: Indonesia · English

Disabling the Submit button helps, but it is not enough. A visitor can refresh, a service worker can replay fetch, or a timeout can trigger a second attempt. Without a unique key the server sees two valid POSTs.

Before fetch, create one token (a UUID) and store it in sessionStorage with the form state. Send the token in an Idempotency-Key header or a hidden field. A supporting backend returns the first response if the same key arrives again.

Do not reuse a key across different submissions. After a 2xx response, drop the token and mint a new one. For 5xx or a network drop, retry with the same key — that is the point.

If the third-party API does not accept that header, still send a clientRequestId in JSON. Log the id in Clincoo so a support ticket can trace a double order.

Test in the Network tab: submit once, then replay the same fetch. The correct result is one server record and two identical client responses.
