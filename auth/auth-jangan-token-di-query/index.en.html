Do Not Put a Session Token in a Clincoo URL Query

A token in the query is stored in history, server logs, and the Referer header. Move it to a header or a cookie scripts cannot read.

This article is available in: Indonesia · English

A share link from app.clincoo.buzz sometimes appends access_token to the query. That URL lands in browser history and analytics logs.

Send the session in an Authorization header or an HttpOnly Secure SameSite cookie. Do not put the secret in the hash if page scripts can still read it.

If an invite link must carry a one-time code, use a short expiring code and exchange it on the server. Do not send the full session token.

When asking AI to fix login, paste the error without the token value. Ask for a header example, not a URL that contains a secret.

Check Network on editor.clincoo.buzz: document requests must not show a token in the query column. Note the finding on blog.clincoo.buzz.
