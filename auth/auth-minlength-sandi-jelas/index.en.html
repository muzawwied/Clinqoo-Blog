Show Password Length Rules on Clincoo Forms

Password checks that fail only after submit make people guess the rules. Use minlength and help text before submit.

This article is also available in: Indonesia · English

Sign-up forms on app.clincoo.buzz often reject a short password after a full reload. People do not learn the rule until a failed attempt.

Add minlength and maxlength on the password input. Put help under the field: at least 12 characters. Wire it with aria-describedby so screen readers announce it.

Skip complex patterns that force a special character. NIST prefers length and a leaked-password check over composition rules. The server must still validate; HTML attributes are only a hint.

Test in editor.clincoo.buzz with an 8-character password. The browser should block submit and show a native or custom message that matches the server rule.

Ask AI to tidy only the help text and attributes. Paste the current password input so it does not add an unsolicited color checklist.
