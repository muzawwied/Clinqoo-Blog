Set Clincoo Session Cookies to HttpOnly and SameSite

A session cookie readable by script is XSS bait. HttpOnly, Secure, and SameSite=Lax hold the token.

This article is also available in: Indonesia · English

A login token stored in localStorage or a cookie without HttpOnly can be stolen by third-party script on a Clincoo page. One small XSS is enough to copy document.cookie.

Send Set-Cookie with HttpOnly; Secure; SameSite=Lax; Path=/ on app.clincoo.buzz. HttpOnly blocks JavaScript. Secure requires HTTPS. SameSite=Lax blocks most cross-site POSTs from carrying the cookie.

Do not put the token in a query string or a header that public logs keep. If the client needs a value, issue a second non-HttpOnly cookie for preferences only, never for the session.

In editor.clincoo.buzz, open DevTools Application → Cookies. After login, HttpOnly and Secure should be checked. If not, fix the server header instead of adding a page polyfill.

Ask AI to summarize the current cookie attributes. Paste the real Set-Cookie snippet; do not ask it to rewrite the whole auth middleware.
