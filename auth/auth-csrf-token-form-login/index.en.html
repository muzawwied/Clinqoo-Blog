Include a CSRF Token on the Clincoo Login Form

A login POST without a CSRF token can be triggered from another site. A hidden field plus SameSite stops cross-site requests.

This article is also available in: Indonesia · English

A sign-in form on app.clincoo.buzz that only posts email and password can be forged by another page. Browsers still send SameSite=Lax cookies on some GET navigations, and older POST flows still leak through.

Generate a random token on the server, store it in the session, and put it in a hidden input named csrf. On POST, compare the body value with the session. If they differ, reject with 403 and no token detail.

Do not put the CSRF token in the query URL. Rotate it after a successful login. Keep the session cookie HttpOnly; the form token may be readable by first-party script.

Test in editor.clincoo.buzz: POST without the csrf field and confirm a reject. Then submit the official login page and confirm success.

Ask AI only to add the hidden input to the markup you paste. Do not let it replace the whole server handler.
