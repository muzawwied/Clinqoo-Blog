Do Not Copy the Dev Env File to Production

Local URLs, keys, and debug flags often ship by accident. Compare variable names, do not copy values.

This article is available in: Indonesian · English

A release from editor.clincoo.buzz fails quietly if the API URL still points at localhost.

Make a list of variable names required in production. Set values only in the release environment, not from the dev file.

Reject the release if DEBUG flags, test tokens, or preview domains appear in production config.

Do not paste the whole env file into an AI chat. Name the empty variables and ask AI to check the list, not the values.

After publish, open app.clincoo.buzz and confirm requests go to the production host, not the dev host.

Record intentional env differences on blog.clincoo.buzz so the next release does not merge the two.
