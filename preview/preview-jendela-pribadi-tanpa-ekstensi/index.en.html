Test the Clincoo Preview in a Private Window without Extensions

Cache and browser extensions hide errors. Open the Clincoo preview URL in a private window before you publish.

This article is available in: Indonesia · English

An editor tab that has been open for hours keeps a service worker, session cookies, and stale CSS. A new visitor does not. A private window is closer to a first visit: empty cache, no automatic login, limited storage.

Copy the Clincoo preview URL, open an incognito window, paste it, then check the tab title, favicon, hero image, and menu links. Disable ad blockers if the private window still loads them. Many "missing images" only appear when a blocker strips an asset domain.

Open the console. CORS errors, font 404s, and mixed content often show up only in a clean session. Note the failing paths, fix them in the editor, deploy again, and retest in a fresh private window — not the same tab.

Repeat on a phone with a private tab if you can. A narrow viewport plus an empty cache shows overflow that never appears on your dark-themed desktop.

Do not treat a hard refresh on your work tab as a substitute. It clears one origin; extensions and login stay. One private-window pass before Publish is more honest.
