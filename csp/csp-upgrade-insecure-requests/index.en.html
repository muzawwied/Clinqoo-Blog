How to Use upgrade-insecure-requests

upgrade-insecure-requests asks the browser to rewrite HTTP URLs to HTTPS before they load. That clears mixed-content warnings without editing every tag. Store the directive in the editor.clincoo.buzz deploy config, then open the app.clincoo.buzz preview and confirm images and scripts still appear.

Do not treat it as a script-src replacement

This directive only upgrades the scheme. Hosts allowed to load scripts are still set by script-src. Use both together, not as substitutes.

Fix sources that have no HTTPS

If a third-party asset does not serve HTTPS, the upgrade fails to load it. Replace the source or host it yourself. Do not drop the directive just so an old asset appears.

Record remaining HTTP assets

List leftover HTTP URLs on blog.clincoo.buzz before deploy so the team knows which ones are upgraded on purpose and which ones must be replaced.
