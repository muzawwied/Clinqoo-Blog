Lock Third-Party Iframes in Clincoo with sandbox and referrerpolicy

Map, video, or booking embeds need a sandbox. Limit iframe permissions so your Clincoo page stays closed.

This article is available in: Indonesia · English

An iframe is the fastest way to drop a map, player, or booking form onto a Clincoo site. Without limits, the framed document can request permissions, open popups, or read the full referrer of your preview URL. That security cost is not worth a paste-and-forget embed.

Add a sandbox attribute. Start strict, then allow only what the widget truly needs: allow-scripts if the player must run, allow-same-origin only when official docs require it. Do not stack every token “so it does not break”. Each token is a permission.

Set referrerpolicy to strict-origin-when-cross-origin, or no-referrer if the service does not need the full URL. Lazy loading protects First Paint. Lock the aspect ratio in CSS so the card does not jump when the iframe finishes loading.

Keep a fallback link outside the iframe: “Open in maps” or “Watch on YouTube”. Strict networks and privacy extensions often block embeds. Visitors should still finish the task without the widget.

Test in Clincoo preview with the console open. If the iframe refuses to load after sandboxing, loosen one token only, then test again. Note the working combination in an HTML comment so collaborators do not strip the protection.
