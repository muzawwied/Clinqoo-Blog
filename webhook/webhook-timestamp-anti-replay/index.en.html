Reject Replay of Clincoo Webhooks with a Timestamp

A valid signature can be resent hours later. Compare the payload timestamp with server time.

This article is also available in: Indonesia · English

HMAC keeps the body from being changed, but it does not stop the event from being replayed. An attacker who copies an old request still passes if you only check the signature.

Require a time field in the header or body, for example Unix seconds. Reject it when the skew is more than five minutes from a clock you trust.

Combine the time check with an idempotent event id. The same event inside the window is still processed once.

Ask AI only to add the timestamp comparison. Paste the handler plus a sample header from the webhook provider.

Test three cases in editor.clincoo.buzz: current time, yesterday, and a missing time field. Only the first may write data on app.clincoo.buzz.
