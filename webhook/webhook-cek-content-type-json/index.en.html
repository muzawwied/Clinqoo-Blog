Reject Clincoo Webhooks that Are Not JSON

Plain text or form-urlencoded bodies break the parser. Check Content-Type before JSON.parse.

This article is also available in: Indonesia · English

Many Clincoo handlers call JSON.parse on request.body at once. A sender with the wrong header or a bot posting HTML makes parse fail and the event vanish without a clear status.

Read the Content-Type header at the start of the handler. Accept only application/json or application/json with a charset. Reply 415 for any other type, then stop.

After the type is correct, cap the text size before parse. Catch SyntaxError and reply 400 with the event id when present.

Ask AI to add the header check only. Paste the webhook handler snippet; do not ask it to regenerate the whole site.

Preview in editor.clincoo.buzz with two requests: valid JSON and plain text. Confirm the second one never writes data.
