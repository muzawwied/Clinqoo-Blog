Reply 2xx on Clincoo Webhooks before Heavy Work

Senders retry when they do not get a fast 2xx. Store the event, reply success, then process.

This article is also available in: Indonesia · English

Webhook senders cap wait time. If a Clincoo page renders images or calls another API before it answers, the sender assumes failure and retries.

Safe order: verify the signature, store the event id, send 200 or 202, then run slow work. The queue can be a list in local JSON processed later.

Do not reply 200 when verification fails. 401 or 400 stops useless retries. Use 5xx only when storing the event truly failed, because 5xx triggers retry.

Ask AI to split receive and process into two functions. One file, two functions, no template rewrite.

Test in editor.clincoo.buzz by delaying the process step. Confirm the 2xx status appears first. Deploy to app.clincoo.buzz after that.
