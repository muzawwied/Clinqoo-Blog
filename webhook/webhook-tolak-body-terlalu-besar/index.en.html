Cap Clincoo Webhook Body Size

Huge payloads lock the editor tab and burn quota. Reject bodies above the limit you set.

This article is also available in: Indonesia · English

A Clincoo webhook endpoint may accept POST with no size cap. One base64 file inside JSON is enough to freeze preview and bloat logs.

Set a limit, for example 64 KB for ordinary events. Read Content-Length when present; otherwise measure the raw body text before parse.

Reply 413 and do not write a file. Log the event id and size, not the full contents. Apply the same rule in the heavy-work queue.

Ask AI to add a size guard on the existing handler. Do not let AI copy the payload into localStorage.

Test in editor.clincoo.buzz with a small body and a large body. Deploy to app.clincoo.buzz only after the large one is cleanly rejected.
