Require an Event-Id Header on Clincoo Webhooks

Without an event id in the header, retries and logs collide. Reject POSTs that lack a unique identifier.

This article is available in: Indonesia · English

Webhook senders retry POSTs after a timeout. Without X-Event-Id or Delivery-Id, a Clincoo handler processes the same event twice.

Read the header first. If it is empty or not a UUID, answer 400. Do not rely only on an id field inside JSON that an attacker can change.

Store ids that already succeeded. A repeat with the same id should return 2xx without writing new data. MDN covers reading headers; GitHub Docs uses X-GitHub-Delivery as a similar pattern.

Ask the AI to add one header-validation branch. Do not let it rewrite the body parser.

Test in app.clincoo.buzz with two identical POSTs. Logs should show one process and one skip.
