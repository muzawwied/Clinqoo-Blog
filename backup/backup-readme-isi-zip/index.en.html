Put a README Inside Every Clincoo Backup ZIP

A ZIP with no notes becomes a puzzle. One README inside the archive explains when and why the backup was made.

This article is available in: Indonesia · English

A dated filename helps, but three months later you forget whether the ZIP was made before a template swap or after an AI generate. Notes outside the archive get separated. Put README.txt at the ZIP root.

Minimum contents: ISO date, Clincoo project URL, reason for the backup (release, before AI, before deleting a page), and the files you meant to change. One paragraph is enough. Do not paste the full diff.

Add a restore test: extract into an empty folder, open index.html in preview, check the logo and one form. If that step fails, the ZIP must not replace the live project.

Keep a checksum on the last line of the README. When the file is re-downloaded from the cloud, compare the hash before overwriting the workspace.

This habit keeps teamwork tidy. Someone else can restore without calling you just to ask which ZIP is safe.
