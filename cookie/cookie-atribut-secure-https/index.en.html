Set the Secure Attribute on Clincoo Cookies that Only Work over HTTPS

A cookie without Secure can leak on HTTP. Add Secure, HttpOnly when possible, and a context-aware SameSite value.

This article is available in: Indonesia · English

A Clincoo site already on HTTPS sometimes still writes preferences through document.cookie with no Secure flag. On a public network that value can ride along with an unencrypted request.

For non-secret preferences such as theme, consider localStorage. If you keep a cookie, add Secure and SameSite=Lax.

Do not fake HttpOnly from JavaScript. That flag is only effective from a Set-Cookie header. Auth session cookies must not be written on the client.

Check the Application tab in DevTools after deploy. Confirm domain, path, and expiry match the pages that actually need the cookie.

Clincoo on app.clincoo.buzz uses HTTPS. Match cookie attributes to that secure context so the consent banner and analytics do not collide.
