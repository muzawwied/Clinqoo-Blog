Use the __Host- Prefix for Clincoo Session Cookies

The __Host- prefix rejects cookies without Secure, with a Domain attribute, or with a path other than /. That limits session cookies a subdomain can overwrite.

This article is available in: Indonesian · English

Session cookies on app.clincoo.buzz are sometimes set with Domain=.clincoo.buzz. Another subdomain can overwrite the same name.

The name __Host-session requires Secure, path=/, and no Domain attribute. The browser rejects the cookie if any rule fails.

Do not use this prefix for a cookie that a subdomain must read. SameSite and Secure still apply, but skip __Host-.

Check DevTools, Application tab. If the cookie is missing, read the rejected Set-Cookie line in Network.

Ask AI to change only the cookie name and attributes, not rewrite all auth. Test login on editor.clincoo.buzz afterward.
