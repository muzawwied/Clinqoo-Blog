Animasi UI Clincoo Pakai requestAnimationFrame, Bukan setInterval

setInterval tidak tahu kapan browser menggambar frame. requestAnimationFrame mengikuti refresh dan berhenti di tab tersembunyi.

Artikel ini tersedia dalam: Indonesia · English

Progress bar, penghitung, atau geser kartu di situs Clincoo sering ditulis dengan setInterval 16 milidetik. Interval itu menebak 60 fps, tapi tidak sinkron dengan vsync. Saat tab di latar, interval tetap jalan dan menguras baterai tanpa ada yang melihat.

Ganti loop visual dengan requestAnimationFrame. Browser memanggil callback tepat sebelum mengecat frame. Di tab tersembunyi, pemanggilan dijeda. Kamu mendapat animasi yang lebih halus tanpa kerja sia-sia.

Simpan id frame dan batalkan dengan cancelAnimationFrame saat komponen dilepas atau pengguna menekan berhenti. Jangan menumpuk dua loop. Hitung posisi dari timestamp di argumen callback, bukan dari asumsi “setiap 16 ms maju 1 piksel”, supaya gerak tetap merata di layar 120 Hz.

Untuk pekerjaan yang bukan visual — polling API atau debounce ketikan — setTimeout atau setInterval masih sah. Bedakan tugas gambar dan tugas data. Campur keduanya dalam satu interval membuat halaman terasa berat saat jaringan lambat.

Uji di pratinjau Clincoo: buka Performance di DevTools, rekam saat animasi jalan, lalu sembunyikan tab. Kalau aktivitas CPU tidak turun, kamu masih memakai timer lama. Ganti, lalu catat pola loop di komentar skrip.
