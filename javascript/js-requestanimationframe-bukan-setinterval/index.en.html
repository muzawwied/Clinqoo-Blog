Animate Clincoo UI with requestAnimationFrame, Not setInterval

setInterval does not know when the browser paints. requestAnimationFrame follows refresh and pauses in hidden tabs.

This article is available in: Indonesia · English

Progress bars, counters, or sliding cards on a Clincoo site are often written with a 16 ms setInterval. That interval guesses 60 fps and is not aligned with vsync. When the tab is in the background, the timer keeps running and drains the battery for no one.

Replace visual loops with requestAnimationFrame. The browser calls your callback just before painting a frame. Hidden tabs pause the calls. You get smoother motion without wasted work.

Store the frame id and cancel it with cancelAnimationFrame when the component unmounts or the user hits stop. Do not stack two loops. Drive position from the timestamp argument, not from “every 16 ms move 1px”, so motion stays even on 120 Hz screens.

For non-visual work — API polling or input debounce — setTimeout or setInterval is still fine. Separate paint work from data work. Mixing both in one interval makes the page feel heavy when the network is slow.

Test in Clincoo preview: open Performance in DevTools, record while the animation runs, then hide the tab. If CPU does not drop, you are still on the old timer. Switch, then note the loop pattern in a script comment.
