Use Intersection Observer to Lazy-load Clincoo Images, Not a Scroll Listener

A window scroll listener causes layout thrash. Intersection Observer is cheaper and widely supported.

This article is available in: Indonesia · English

Older templates delay images with window.addEventListener('scroll'). Every pan forces the browser to recompute offsets, and on a Clincoo page full of cards that feels janky.

Intersection Observer exists for the question whether an element is visible. You register images, the browser calls you when the intersection ratio changes, and only then do you copy data-src into src. You do not call getBoundingClientRect on every frame.

Start simple: root null (the viewport), rootMargin 200px so images near the fold start loading, threshold 0. After src is set, unobserve so the observer does not stay alive.

Do not mix the observer with innerHTML that rewrites the list. If cards are replaced, observe the new nodes. If you only append items, observe those items — the same idea as event delegation.

As a fallback, loading="lazy" on img is enough in modern browsers. The observer helps when you need a margin, a placeholder, or to delay iframes and other widgets, not only images.

Test in Clincoo preview on a slow network. Keep a real src on first-screen images so LCP does not wait for the observer.
