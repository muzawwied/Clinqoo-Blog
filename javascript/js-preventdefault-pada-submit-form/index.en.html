Call preventDefault on Clincoo Form Submit before Fetch

Without preventDefault the browser submits the form and reloads the page before fetch finishes.

This article is available in: Indonesia · English

Contact forms in a Clincoo project are often sent with fetch so a success message can appear without leaving the page. If the submit listener forgets event.preventDefault(), the browser still runs the default action: navigate to the action URL or reload. The fetch response loses the race to that reload.

Bind the listener on the form element, not only on the button. A type="submit" button can be fired with Enter from any field. A button-only listener misses keyboard submission.

After preventDefault, disable the send button until fetch finishes so double-clicks do not stack requests. Show status text near the form, not only in the console. If fetch fails, enable the button again and explain what to retry.

Do not mix action="#" with an inconsistent handler. If JavaScript is turned off, the form still needs a sensible action or at least a message that sending requires script. Progressive enhancement keeps the form from feeling broken.

Test three paths: click the button, press Enter in an input, and submit with the network cut. All three should stay on the same page and give readable feedback.
