Clear Stale Storage Keys when a Clincoo Site Version Changes

localStorage keys from an old release collide with a new schema and break drafts or preferences.

Indonesia · English

A Clincoo site that keeps form drafts or theme choice in localStorage will break if you change the JSON shape with no migration plan. The MDN Storage API has no built-in version; you mark the schema.

Keep one version key, for example clincoo-store-v. On load, compare it with APP_STORE_VERSION. If they differ, delete only your app keys. Do not call clear() blindly when other scripts share the origin.

web.dev notes quota is shared with cookies, Cache Storage, and IndexedDB. Zombie data from three releases ago hastens QuotaExceededError. After migrate, rewrite drafts to the new shape or let visitors refill with a short notice.

Wrap removeItem and setItem in try/catch. Private mode and a full quota still throw. Do not store tokens; another article in this category already covers that.

Ask the AI to add one migrateStorage() function and a version number in a single file. Refuse a full page-script rewrite. Test by setting an old version in Application > Local Storage, reload, and confirm stale keys are gone.

Sources: MDN localStorage, MDN Storage API, web.dev Storage for the web.
