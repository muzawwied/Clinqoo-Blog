Watch Clincoo Node Changes with MutationObserver, Not Polling

Polling innerHTML every 200 ms taxes the Clincoo preview. MutationObserver only watches one container.

Indonesia · English

Many Clincoo templates still use setInterval to see whether a list changed. That loop reads the DOM even when nothing moved, then forces layout in preview. MutationObserver only wakes when a child is added, removed, or an attribute changes.

Attach the observer to one container you own, such as #daftar or .cart-items. Do not watch document.body: every tooltip or focus class will fire the callback. childList: true and subtree: false are usually enough for a flat list.

Inside the callback, read mutations once. If you only need "a new item appeared", do not querySelectorAll the whole page. Use mutation.addedNodes, then apply classList or textContent on that node. Call disconnect() when the page changes or a modal closes.

Test in the Clincoo preview: add one item with a button and confirm the handler runs with no interval in the console. If the AI suggests setInterval("check the DOM"), refuse and ask for a narrow MutationObserver.

Hidden polling is hard to find when performance drops. An observer bound to one container makes the script's intent readable in the inspector and cheaper on the main thread.
