Jangan Biarkan Redirect 302 Mengubah POST Clincoo Jadi GET

Redirect 302 pada POST sering diikuti browser sebagai GET tanpa body. Data simpan hilang.

Artikel ini tersedia dalam: Indonesia · English

Jika API app.clincoo.buzz membalas 302 ke URL login atau slash tambahan, fetch mengikuti redirect dan method bisa menjadi GET.

Pakai redirect: 'manual' saat debug. Baca Location. Perbaiki trailing slash atau HTTPS di origin, bukan di klien.

Untuk pindah permanen, 308 menjaga method. 303 memanggil GET dengan sadar setelah POST berhasil.

Tempel rantai redirect dari Network ke AI. Jangan minta AI menambah proxy acak sebelum Anda lihat status 302.

editor.clincoo.buzz dan blog.clincoo.buzz harus memakai URL kanonik agar POST tidak berbelok.
