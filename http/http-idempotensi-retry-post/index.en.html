Do Not Retry a Clincoo POST Without an Idempotency Key

Retrying POST after a timeout can duplicate a draft. Use a unique key per save action.

This article is available in: Indonesia · English

A timeout on editor.clincoo.buzz pushes users to hit Save again. The app.clincoo.buzz server may already have written the first draft.

Send an Idempotency-Key header or a UUID requestId field per save click. The server rejects duplicates with the same status.

Idempotent GET and PUT may be retried. A create POST may not, unless the server honors the same key.

Paste two request logs that share an id to AI. Do not ask AI to add automatic retries on every POST.

Clincoo on blog.clincoo.buzz does not create resources via POST; in the app, an idempotency key prevents twin drafts.
