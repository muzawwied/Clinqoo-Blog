Separate Network Failures from HTTP Status in Clincoo

A TypeError from fetch is not a 500. Do not show a server message when the cable is unplugged.

This article is available in: Indonesia · English

On editor.clincoo.buzz, fetch that fails because you are offline throws TypeError. A 500 still resolves. Mixing them misleads users.

Wrap fetch in try/catch. Catch = network or CORS. Then plus status >= 400 = a server reply. Show different copy.

Treat navigator.onLine as a hint, not proof. Online true does not mean app.clincoo.buzz is reachable.

Paste the full TypeError stack to AI. Do not ask AI to treat every failure as 'server down'.

Clincoo on blog.clincoo.buzz does not call an API; in the app, this split keeps error messages honest.
