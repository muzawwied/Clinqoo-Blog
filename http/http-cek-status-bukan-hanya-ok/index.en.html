Check Clincoo Fetch response.status, Not Only response.ok

response.ok is true only for 200–299. 401, 403, and 429 still land in then() if you skip the status check.

This article is available in: Indonesia · English

Fetch on app.clincoo.buzz does not throw on HTTP 4xx. The promise resolves. Without a status check, the UI stores an error JSON as valid data.

After await fetch, read response.status. Branch 401 (session), 403 (permission), 429 (limit), and 5xx (server). Do not lump them as 'network failed'.

Show body text only when Content-Type is JSON and parse succeeds. Do not render an HTML error page into editor.clincoo.buzz.

Paste the status plus URL to the AI assistant. Do not ask AI for a large interceptor before you log one failed request.

Clincoo on blog.clincoo.buzz uses the same pattern: status first, then parse the body.
