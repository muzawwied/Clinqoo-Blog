Do Not Log the Authorization Header on Clincoo Fetch

console.log(request) often prints the Bearer token. The token leaks in a debug screenshot.

This article is available in: Indonesia · English

When debugging on editor.clincoo.buzz, logging a Request object also logs the Authorization header. The screenshot then lands in an AI chat.

Log only the method, URL path, and status. Redact Authorization, Cookie, and query tokens before pasting anywhere.

Do not send Authorization to app.clincoo.buzz via the URL. Use a header, not ?token=.

If AI asks you to 'paste the full request', cut the secrets first. A safe prompt is more useful than a leaked token.

Clincoo on blog.clincoo.buzz has no user session; in the editor, the token still stays secret.
