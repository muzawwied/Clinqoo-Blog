Do Not Access window or localStorage from a Clincoo Worker

Workers have no DOM. Reading window or localStorage throws ReferenceError and kills the task.

This article is available in: Indonesia · English

Copying page code into a worker in editor.clincoo.buzz often brings localStorage.getItem. That API does not exist in a worker.

Send needed data with postMessage from the main tab. Keep tokens only on the app.clincoo.buzz page, not in the worker.

If AI pastes a snippet that uses document, cut it first. A worker may only compute, parse, or transform data.

Test with one postMessage carrying a plain object. If the worker crashes, open Sources then worker, not only the main console.

Clincoo on blog.clincoo.buzz splits UI and compute: the worker does not touch browser storage.
