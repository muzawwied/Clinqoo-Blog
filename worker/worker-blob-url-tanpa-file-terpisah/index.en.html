Create a Clincoo Worker from a Blob URL When You Have No Separate File

Static hosting sometimes rejects a worker across folders. A Blob URL embeds the script on the same page.

This article is available in: Indonesia · English

new Worker('./worker.js') fails in some Clincoo previews if the file MIME is wrong or the relative path crosses folders. The console says failed to load worker script. The page still runs; the heavy job never starts.

Wrap the worker body as a string or template literal, make a Blob with type 'text/javascript', then URL.createObjectURL(blob). new Worker(url) loads the script from the same page origin. After the worker is ready, URL.revokeObjectURL so blobs do not pile up.

This fits short workers: sort, hash, or filter a list. For a long worker, a separate file in the Clincoo repo is clearer and easier to test alone. A Blob is the fallback when a separate file is blocked.

Do not embed secrets in the worker string. Anyone can read a static page source. Test in editor.clincoo.buzz that onmessage still receives a result after the Blob URL is revoked.

A site on app.clincoo.buzz is static files. A Blob URL avoids a fragile worker path without adding a server.
