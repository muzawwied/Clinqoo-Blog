Limit Clincoo Worker Message Size so the Tab Does Not Bloat

postMessage of a huge object clones memory twice. Trim the payload or transfer a buffer; do not send the whole project.

This article is available in: Indonesia · English

A Clincoo page sends the full product array plus HTML to the worker on every filter. The tab bloats and preview feels slow even if the UI is not fully frozen.

In editor.clincoo.buzz send only the fields you compute: id, price, stock. Keep markup on the main thread. For binary data, use a transferable ArrayBuffer.

Set a rough cap: reject payloads of several megabytes and show "data too large, filter first". Do not let silent clones eat RAM.

Measure in DevTools Memory before and after a filter. If the heap doubles on every message, the payload is still too big.

A Clincoo static site stays light when your script does not duplicate data. The worker should compute, not store a second copy of the project.
