Batasi Ukuran Pesan ke Worker Clincoo agar Tab Tidak Menggelembung

postMessage objek raksasa menyalin memori dua kali. Potong payload atau pindahkan buffer, jangan kirim seluruh proyek.

Artikel ini tersedia dalam: Indonesia · English

Halaman Clincoo mengirim seluruh array produk plus HTML ke worker setiap filter. Tab membengkak dan pratinjau terasa lambat meski UI tidak membeku total.

Di editor.clincoo.buzz kirim hanya kolom yang dihitung: id, harga, stok. Sisakan markup di thread utama. Jika data biner, gunakan transferable ArrayBuffer.

Tetapkan batas kasar, misalnya tolak payload di atas beberapa megabyte dan tampilkan pesan "data terlalu besar, saring dulu". Jangan biarkan klon diam-diam menghabiskan RAM.

Ukur di DevTools Memory sebelum dan sesudah filter. Jika heap naik dua kali lipat tiap pesan, payload masih kebesaran.

Situs statis Clincoo tetap ringan jika skripmu tidak menggandakan data. Worker membantu hitung, bukan menjadi gudang salinan proyek.
