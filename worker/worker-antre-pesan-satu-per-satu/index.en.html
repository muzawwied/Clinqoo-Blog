Queue postMessage to a Clincoo Worker; Do Not Flood It

Sending hundreds of messages with no queue makes the worker and UI race. One active job is safer.

This article is available in: Indonesia · English

A Clincoo search input fires postMessage on every keypress. The worker still processes an old letter when a new one arrives.

Keep a queue on the main thread. Send the next item only after an onmessage result or error.

For typing, debounce 200 ms then send one latest payload. Drop a stale queue.

Test in the editor.clincoo.buzz preview. The shown result must match the last text, not a mid-type letter.

Clincoo does not queue worker jobs for you. A queue in your script keeps app.clincoo.buzz from showing stale results.
