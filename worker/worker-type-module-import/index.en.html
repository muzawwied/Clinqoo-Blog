Use type module on a Clincoo Worker so import Works

import fails in a classic worker. type: 'module' matches the ES scripts in the editor.

This article is available in: Indonesia · English

Many Clincoo templates use import/export in page scripts. Copying the same function into a classic worker.js throws SyntaxError: Cannot use import statement outside a module. The job never runs.

Create the worker with new Worker(url, { type: 'module' }). In the worker file, import pure functions — sorter, parser, hasher — from the same module the page uses. Do not import a module that touches document; a module worker still has no DOM.

Import paths are relative to the worker file, not the page. Test in editor.clincoo.buzz preview. If a module 404s, check the assets folder and the required .js extension on the specifier.

Module workers support top-level await. Still send results with postMessage; do not rely on the constructor return. Attach onerror the same way as a classic worker.

A static site on app.clincoo.buzz ships files as they are. type: 'module' keeps one source of truth for logic, with no bundler and no copied functions in two files.
