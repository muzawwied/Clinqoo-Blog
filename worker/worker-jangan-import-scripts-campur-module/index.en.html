Do Not Mix importScripts with a Clincoo Module Worker

A type module worker rejects importScripts. Pick one model: ES import or classic scripts, not both.

This article is available in: Indonesia · English

A Clincoo worker file is created with type: 'module' then calls importScripts('util.js'). The browser throws and the job never starts.

In editor.clincoo.buzz pick one style. Module: new Worker(url, { type: 'module' }) and import { hitung } from './util.js'. Classic: a Worker without type module and importScripts.

Shared utils must be exported in that same style. Do not rely on globals from importScripts inside a module.

Watch the preview console when a worker fails silently. A message about importScripts in a module worker is the mixed-model signal.

Clincoo static hosting serves files as they are. Consistent modules keep app.clincoo.buzz from depending on browser guesswork.
