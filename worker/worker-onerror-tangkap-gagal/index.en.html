Catch Clincoo Worker Errors with onerror, Do Not Stay Silent

A worker that throws without a handler looks hung. The UI waits for a result that never arrives.

This article is available in: Indonesia · English

In editor.clincoo.buzz a Calculate button starts a worker and shows a spinner. If the worker throws on bad data, the spinner never leaves. Visitors think app.clincoo.buzz froze even though the main thread is fine.

Attach worker.onerror and worker.onmessageerror before the first postMessage. In onerror, log filename, lineno, and message, then send a failed status to the UI. Do not rely only on try/catch inside the worker — an unwrapped exception still surfaces as an event on the main thread.

Also set self.onerror inside worker.js. postMessage an object {ok:false, reason} so the page can show a human-readable line instead of silently terminating the worker.

Test in Clincoo preview by sending an empty payload on purpose. The spinner must become “Calculation failed, try again” within a second. If it does not, the handler is missing.

A static Clincoo site has no server log. The only worker error trail is what you render on the page. Catch first, then terminate.
