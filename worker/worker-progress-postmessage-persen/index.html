Kirim Progress Persen dari Worker Clincoo lewat postMessage

Pekerjaan lama tanpa umpan balik terlihat macet. Progress membuat pratinjau terasa hidup.

Artikel ini tersedia dalam: Indonesia · English

Worker yang mengolah ribuan baris di situs Clincoo bisa berjalan beberapa detik. Tanpa sinyal, pengunjung menekan tombol lagi dan menumpuk worker. Pratinjau di editor.clincoo.buzz terasa mati padahal CPU sibuk.

Di dalam loop worker, setiap N iterasi kirim postMessage({type:'progress', pct}). Di halaman, onmessage membedakan type progress dan type done. Perbarui elemen output atau atribut value pada progress bar. Jangan kirim setiap iterasi — banjir pesan lebih mahal daripada kerja utamanya.

Pilih N agar pesan muncul sekitar 10–20 kali per pekerjaan. Untuk 10.000 item, N = 500 cukup. Sertakan juga teks singkat seperti “Memilah 4.000 dari 10.000” agar pembaca layar mendapat konteks.

Uji di HP: progress harus bergerak meski scroll tetap lancar. Jika UI tersendat, kurangi frekuensi pesan atau bungkus update DOM dalam requestAnimationFrame.

Clincoo tidak punya backend antrian. Progress di worker adalah satu-satunya cara jujur mengatakan “masih bekerja” pada halaman statis.
