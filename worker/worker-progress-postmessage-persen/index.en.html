Send Percent Progress from a Clincoo Worker via postMessage

A long job with no feedback looks stuck. Progress makes the preview feel alive.

This article is available in: Indonesia · English

A worker that processes thousands of rows on a Clincoo site can run for seconds. With no signal, visitors click again and stack workers. Preview in editor.clincoo.buzz feels dead while the CPU is busy.

Inside the worker loop, every N iterations postMessage({type:'progress', pct}). On the page, onmessage tells progress apart from done. Update an output element or the value on a progress bar. Do not send every iteration — a flood of messages costs more than the work itself.

Pick N so about 10–20 messages appear per job. For 10,000 items, N = 500 is enough. Include a short line such as “Sorting 4,000 of 10,000” so a screen reader gets context.

Test on a phone: progress must move while scroll stays smooth. If the UI stutters, send fewer messages or wrap DOM updates in requestAnimationFrame.

Clincoo has no backend queue. Worker progress is the only honest way to say “still working” on a static page.
