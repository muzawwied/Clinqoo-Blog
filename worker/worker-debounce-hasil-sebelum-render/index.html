Debounce Hasil Worker Clincoo sebelum Render DOM

onmessage yang langsung menulis DOM pada setiap tick membuat layout bergelombang. Satukan hasil, lalu render sekali.

Artikel ini tersedia dalam: Indonesia · English

Worker Clincoo mengirim progress tiap 50 baris. Handler utama menulis innerHTML daftar lengkap setiap pesan, sehingga scroll meloncat.

Di editor.clincoo.buzz simpan hasil terakhir di variabel. Pakai requestAnimationFrame atau timeout pendek untuk menggambar sekali per bingkai, bukan per pesan.

Progress persen cukup mengubah teks satu elemen. Jangan membangun ulang tabel sampai status selesai atau pengguna meminta cuplikan.

Uji dengan data besar di pratinjau. FPS harus tetap terasa lancar; jika daftar berkedip, debounce belum cukup.

Thread utama Clincoo tetap bertanggung jawab pada DOM. Worker menghitung; halaman merender dengan hemat agar app.clincoo.buzz terasa tenang.
