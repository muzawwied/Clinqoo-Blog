Clincoo Database: Data Tables and Per-Project API

The Database page in Clincoo project settings is where you store and manage your app's data in clean tables — accessible through the API anytime. Every Clincoo project gets its own separate database, so data never mixes between projects, and your deployed app can read and write its data with its own access key.

This guide walks through the whole page: activation, creating tables, filling in data, app access keys, API usage examples, and summary charts.

Activation and one database per project

The Clincoo database is activated per project: open the Database tab in project settings, click Activate Database once, and the feature is ready — no server setup, no extra configuration. If a table you expect is missing, check the project name at the top of the page: since each project has its own database, other projects' tables simply do not appear here.

Creating tables and filling in data

The flow is designed as four steps from zero to a connected app:

  1. Create a table. Click Create table, give it a name, then define its columns — e.g. a users table with name and email columns.
  2. Fill in data. Open the table, then add, edit, or delete rows anytime — data saves instantly.
  3. Create an access key. In the App access section, create the key and keep it safe.
  4. Connect your app. Paste the key as a Bearer token in your app code — a full usage example sits right below the key.

App access: API keys

Apps you deploy access the project database through an API key, sent as a Bearer token in the Authorization header of every request. Create the key from the Database page, store it safely, then paste it into your app code.

The key can be replaced anytime via Replace key — and once replaced, the old key stops working automatically. That is a healthy rotation pattern: if a key is suspected leaked, replace it and update your app with the new one.

API usage example

Two main endpoints live under https://app.clincoo.buzz/v1/db: /v1/db/tables to manage tables and /v1/db/rows to read and write data rows. Reading data looks exactly like the example shown on the Database page:

fetch('https://app.clincoo.buzz/v1/db/rows?table=name', {
  headers: { Authorization: 'Bearer YOUR_PROJECT_KEY' }
})

The example on the Database page automatically shows your project's active key, so you can copy and run it as-is.

Database summary charts

The page also shows Charts that fill themselves from your tables and rows, with no setup:

  • Rows per table — total rows stored in each table.
  • Tables created per day — table creation activity.
  • Row composition per table — each table's share of the total.
  • Table spread: columns vs rows — each table's position by size.
  • Activity per day — tables and rows born each day.

Every chart has a Save button to download it as an image — handy for reports or team documentation.
