Clincoo Database: Store Data Straight from Your Backend Function

Backend functions in Clincoo do more than run logic — every function automatically gets a built-in Database: a ready-to-use db object for storing data that persists permanently, with no database server to set up, no external connection, and no configuration at all. Data is isolated per account: your functions only ever see your own account's data, on app.clincoo.buzz.

How to use it: code examples

Nothing to import — just use db with await. A visit counter:

export default async function (args) {
  const total = ((await db.get('visits')) || 0) + 1;
  await db.set('visits', total);
  return { total_visits: total };
}

Storing and reading a collection with a prefix:

export default async function (args) {
  await db.set('message:001', { name: args.name, body: args.body });
  const all = await db.list('message:'); // latest 200 entries
  return { count: all.length };
}

The five database operations

OperationPurposeResult
db.get(key)Reads one value by its key.The stored value, or null if absent.
db.set(key, value)Saves or overwrites one value; the value can be a string or JSON object.true on success.
db.del(key)Deletes one value.true on success.
db.list(prefix)Fetches every value whose key starts with the prefix.Up to 200 latest entries (sorted by most recently updated).
db.count()Monitors your account's storage usage.The rows and bytes you are using.

Data limits

Each entry has sensible limits: keys up to 512 characters and values up to 100 KB per entry.

Performance tips

  • Use key prefixes (for example message:001) so collections are easy to read with list(prefix).
  • Read batches with list instead of looping get one by one — list fetches many values in a single call.
  • Store summary numbers or aggregates when writing, instead of recomputing everything when reading.
  • Track usage with count() from time to time.
  • For temporary data, delete it with del once it is no longer needed to keep storage free.

Frequently asked questions

Do I need to set up a database myself?

No. The built-in database is available inside functions right away — just use the db object in code.

Does data disappear when the function ends?

No. Data is stored permanently and remains on every future call.

What kind of values can be stored?

Strings and JSON objects. Values saved as objects are returned as objects when read.

Is there a size limit per entry?

Yes. Keys up to 512 characters and values up to 100 KB per entry.

Can a function read another account's data?

No. Per-account isolation means every function only ever sees its own account's data.
