Record Lighthouse Scores for Each Clincoo Page Release

Today's green scores vanish without notes. Store Performance, Accessibility, Best Practices, and SEO for every Clincoo release.

This article is available in: Indonesia · English

Lighthouse in DevTools gives four numbers. Without an archive you cannot tell whether a new hero hurt Performance or whether form labels improved Accessibility. Good release notes keep those numbers next to an ISO date.

Create docs/lighthouse.md or a changelog section. Each line: date, preview or live URL, four scores, and one sentence cause (for example “preload heading font”). Do not paste the full JSON report — you need the trend.

Run the audit in a private window with cache disabled so numbers are comparable. Also record the device: desktop versus mobile yields different LCP. web.dev explains the metrics; Chrome docs explain how to export a report.

When AI or a new teammate proposes a heavy animation, point at the previous score line. Rejecting a feature becomes data, not taste.

After a Clincoo deploy, rerun the audit on the public URL. If live scores sit far below preview, the usual cause is asset paths or CDN cache — write down the gap so the next release does not guess again.
