Clincoo Email API Keys: Manage Access and Sender Identity

2026-10-05

The API Keys tab in your project settings (Email → Kunci API) is where you manage Clincoo Email API access: view and copy the project key, regenerate it, disable it, and set the sender identity — the display name and address recipients see.

Viewing and copying the key

Once the project email feature is active, the API key appears right in this tab. The Salin (Copy) button copies it to your clipboard in one tap — no settings digging required. One key represents the whole project: a single key covers every send-email request from your deployed site.

Regenerating and disabling

Two management buttons sit next to the key:

  1. Buat ulang kunci (Regenerate) — replaces the key with a new one. Do this when the old key is suspected leaked, or for routine rotation. The old key stops working immediately, so update the key value in your deployed site.
  2. Nonaktifkan (Disable) — temporarily cuts off all API sending without deleting the key. Ideal when you want to pause deliveries without touching configuration; re-enable anytime.

Sender identity

The sender identity section controls who appears as the sender of your emails:

  1. Display name — the name shown in the recipient’s inbox, like your brand name.
  2. Sender address — must use the @clincoo.buzz domain. Availability is checked live as you type: green means available, red means taken.

Press Simpan Pengirim (Save Sender) to apply. If you never set a custom identity, emails still send with a default identity based on your project name.

Safe key handling

  1. Store the key as an environment variable, not hardcoded.
  2. Never write the key into your repository — follow the never commit API keys guide.
  3. Rotate the key whenever in doubt, and disable it while your site is not sending email.

Usage example

The key goes in the Authorization: Bearer header of every request to the Clincoo Email API. The full guide to sending email from your deployed site — with example requests — is in Sending Email from a Deployed Site.

FAQ

Can one key be used for other projects?

No. Keys are isolated per project — each project has its own key and sender identity.

I lost or never saved my key — what now?

Open the API Keys tab — the key is always visible there. If you have security concerns, use Regenerate to replace it.

Why must the sender address be @clincoo.buzz?

The @clincoo.buzz address keeps emails from your project sending with a consistent, verified identity.

What is the difference between disabling and regenerating the key?

Disable only pauses sending — the key stays the same and can be re-enabled. Regenerate replaces the key, so your deployed site must switch to the new one.
