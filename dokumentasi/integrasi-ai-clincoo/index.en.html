Clincoo AI Integrations: Models, Secrets, and Per-Project API

The AI Integrations page in Clincoo project settings — labeled "AI Router: models and secrets per project" — is the AI control center for a single project. From here you set the default model used by your project's AI features, manage the API secret, test the connection, and monitor usage logs, costs, and analytics. All from one page.

This guide walks through the entire page: the Clincoo Open API, the default-model setting, the secret lifecycle, call examples, connection testing, usage logs, and analytics with API credits.

Clincoo Open API: OpenAI-compatible format

The core of this page is the Clincoo Open API: Clincoo's built-in API with an OpenAI-compatible format. Apps or SDKs written for OpenAI (such as the openai library) can usually be pointed at Clincoo by simply switching the base URL to https://app.clincoo.buzz/v1 and using your project secret — no integration rewrite needed.

Two main endpoints: /v1/chat/completions for chat (generative) calls and /v1/models to list available models. All models are managed and served by Clincoo — no third-party API keys, no model infrastructure to maintain, just one Clincoo secret.

The model you pick as the Default Model is used by the project's AI features. Beyond the default, every other model can still be called directly with the project secret — just pass the model id (e.g. clincoo/glm-5.2) in the model parameter of the request.

API secret: one unique key per project

Every Clincoo project gets its own distinct secret. External applications use this secret to call the Clincoo Open API on your project's behalf, sent as an Authorization: Bearer header to /v1/chat/completions.

Four actions are available on this page:

  • Create New Secret — for projects that have none yet; the secret works immediately.
  • Copy — copies the secret to your clipboard for use in your app.
  • Replace Secret — retires the old secret and issues a new one; the rotation move when a secret is suspected leaked.
  • Revoke — disables the secret; calls using it are rejected.

Since the secret grants full access to your project's AI quota, keep it safe: never hard-code it in a frontend or a public repo. The right practice is storing it as an environment variable or server-side secret in your application.

Call example and Test Connection

The page provides a cURL example that automatically follows the currently selected secret and model — copy it, paste into a terminal, and run. The call uses the Authorization: Bearer header with your project secret, exactly like this:

curl https://app.clincoo.buzz/v1/chat/completions \
  -H "Authorization: Bearer <YOUR_PROJECT_SECRET>" \
  -H "Content-Type: application/json" \
  -d '{ "model": "clincoo/auto", "messages": [{ "role": "user", "content": "Hello!" }] }'

Not sure the secret and endpoint work? Press Test Connection: Clincoo sends one small call to the Clincoo Open API using the project secret and shows the result right on the page — no terminal needed.

Usage logs

Every call made to the Clincoo Open API for your project is recorded in Usage Logs. Filter by status (All, Success, Failed) and export the history to CSV or JSON for deeper analysis. If no calls have been made yet, the page shows an empty state until the first call is logged.

Analytics & Usage and API credits

The Analytics & Usage section summarizes your project's AI performance and consumption from the recorded logs:

  • Summary — total requests, total tokens, and total cost in dollars.
  • API credits — credits used today and this month; daily credits reset every day, monthly credits at the start of each month.
  • Request status — success vs failed calls.
  • Daily usage — a chart of the last 14 days.
  • Average latency per model and usage per model — see which models answer most often and fastest.

Benefits for your workflow

  • Add AI to external apps (backends, bots, automations) through an API with a widely familiar format.
  • Change the project's default model anytime without touching call code — or call another model per request via the model parameter.
  • Rotate secrets routinely with Replace and Revoke to keep things secure.
  • Track cost and performance per model, then pick the most efficient mix for your project.
