Replace Silent Spinners with Announced Clincoo Skeletons

A spinning circle with no status text feels stuck. Use a content skeleton, aria-busy, and a short done message.

This article is available in: Indonesia · English

Clincoo list cards often show a centered spinner during fetch. The layout jumps when data arrives. Keyboard users cannot tell which region is busy, and the animation keeps running even when prefers-reduced-motion is on.

Draw a skeleton that matches real card height: title, two lines, button. Mark the container aria-busy="true" while loading. When data is ready, swap the skeleton, set busy false, and announce through a status region if the list matters.

Do not let the skeleton shimmer forever. Cap the shine or turn it off when the user prefers reduced motion. A timeout should show an empty state or failure message, not an eternal frame.

Ask AI to swap the spinner for skeleton markup plus two classes. Test in editor.clincoo.buzz with a slowed network. Confirm focus does not jump onto newly inserted nodes without a reason.

An announced skeleton keeps layout and expectation intact. Deploy to app.clincoo.buzz after loading cards no longer shove the CTA below them.
