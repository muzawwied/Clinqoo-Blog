Format the Document before Commit, Not After

A diff full of whitespace hides real changes. Format first, then review the lines that remain.

This article is available in: Indonesian · English

On editor.clincoo.buzz, save often triggers auto-format. If that happens after commit, history becomes two confusing steps.

Run format on the touched files before commit. Confirm the diff contains only behavior changes.

Do not format the whole repository in the same commit as a bugfix. Split them so review can reject one part.

If AI tidies the whole file, ask it to limit the change to the function you edited. Reject a diff that only changes quotes or indent outside that area.

Read the app.clincoo.buzz preview after format. A formatter can break sensitive HTML strings.

Write the team format rule on blog.clincoo.buzz so contributors do not reformat the universe again.
