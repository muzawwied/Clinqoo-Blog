Use Stale-While-Revalidate so Clincoo Assets Stay Fast when Almost Offline

Serve cache first, refresh in the background. This strategy keeps Clincoo CSS and images visible on a slow network.

This article is available in: Indonesia · English

Waiting on the network before showing CSS makes a Clincoo site look empty. When the signal is about to drop, an existing cache is more useful than a spinner.

In the service worker, for stylesheet, font, and image requests: if a cache hit exists, return it immediately. In the background, fetch the network and rewrite the cache. That is stale-while-revalidate.

Do not apply this pattern to HTML pages that change often and have no version. For documents, network-first plus an offline fallback is safer.

Name caches with a version, for example clincoo-static-v2, so a new worker can delete old caches on activate. Ask Clincoo AI to change only the static-asset fetch branch.

Clincoo does not pick a cache strategy for you. Stale-while-revalidate in editor.clincoo.buzz keeps app.clincoo.buzz feeling fast even as the network wobbles.
