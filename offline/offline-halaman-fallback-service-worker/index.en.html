Provide an Offline Fallback Page in a Clincoo Site Service Worker

When navigation fails because the network dropped, serve a cached fallback page instead of a blank browser error.

This article is available in: Indonesia · English

A Clincoo visitor who opens an inner link while the signal drops often sees the browser default error page. That feels like a broken site when only the network is gone.

Create a simple offline.html in the editor.clincoo.buzz workspace: a clear title, one explanation paragraph, and a link back home. Cache that file when the service worker installs.

In the fetch event, if the request is a navigation and the network fetch fails, return the cached offline.html. Do not use this fallback for CSS or images so already-cached pages stay intact.

Test in DevTools Offline mode. Open a URL that is not cached: the fallback should appear. Open a cached page: the original content should still show.

Ask Clincoo AI to add only the navigation fetch handler, not rewrite the whole worker. A polite fallback keeps trust on app.clincoo.buzz when the train enters a tunnel.
