Store Large Clincoo Content in IndexedDB, Not localStorage

localStorage fills up fast and blocks the tab. IndexedDB is a better fit for long drafts and Clincoo offline queues.

This article is available in: Indonesia · English

An existing article suggests localStorage for drafts. That is enough for a short title. A full page body, base64 images, or a form queue will hit the quota and freeze the tab.

Open an IndexedDB database named clincoo-offline with a drafts object store. Save objects {id, updatedAt, body}. Asynchronous work does not block the UI in editor.clincoo.buzz.

Handle quota: if a request fails with QuotaExceededError, delete the oldest draft or ask the user to export. Do not silently drop the newest data.

Test under Application > IndexedDB in DevTools. Ask Clincoo AI to write only a put/get wrapper, not replace a save flow that already works.

Clincoo does not ship a client database. IndexedDB keeps drafts on app.clincoo.buzz alive through a much longer outage than a localStorage session.
