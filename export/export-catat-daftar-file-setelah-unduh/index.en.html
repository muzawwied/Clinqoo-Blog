Record a File List after Downloading a Clincoo Project Export

After you download a Clincoo zip, write down key files so a host move does not drop assets or pages.

This article is available in: Indonesian · English

A Clincoo export is usually a static archive: HTML, CSS, JS, images, and a favicon. Many people upload to a new host without inspecting the zip. Missing files show up only as 404s in production.

Open the zip locally. Write a short list: index.html, other pages, the assets folder, robots.txt, and font files. Compare it with the tree in editor.clincoo.buzz. Case differences often break links on Linux hosts.

Keep that list in a README or project note. When you upload through Git, the same list becomes a commit checklist. GitHub Docs stresses that a repository should hold every file the site needs to render, not only the home page.

After upload, open every path from the list in a browser. Do not test the home page alone. Hero images, CSS, and form scripts are the files most often lost when relative paths change.

A file list makes the export auditable. Clincoo gives you a copy; completeness before you switch DNS is still your job.
