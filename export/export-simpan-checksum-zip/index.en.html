Save a Checksum of the Clincoo Export Zip before Moving Hosts

A truncated export zip often shows up only after DNS moves. Record a checksum before you upload to the new host.

Indonesia · English

After you export from Clincoo, the zip can truncate on a slow network or be saved twice under similar names. Without a fingerprint you upload the wrong copy and only notice when CSS or images 404.

Compute SHA-256 locally as soon as the download finishes. On macOS or Linux: shasum -a 256 project.zip. In Windows PowerShell: Get-FileHash project.zip -Algorithm SHA256. Paste the digest into the project README or a release note.

Before you unzip on the server or into a backup folder, hash again. If it differs, download again from the Clincoo editor. Do not patch a broken zip by copying files from an older dump: relative paths get mixed.

Store the export date and project title on the same line as the hash. A teammate moving hosts a week later should not guess which zip was "the last good one".

Test the zip locally: open index.html via a simple static server, check favicon, robots, and relative assets. Then upload. A checksum plus a local smoke test is cheaper than rolling back DNS.
