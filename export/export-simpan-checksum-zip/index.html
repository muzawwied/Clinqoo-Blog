Simpan Checksum Zip Ekspor Clincoo sebelum Pindah Host

Zip ekspor yang rusak saat unduh baru ketahuan setelah DNS berpindah. Catat checksum sebelum unggah ke host baru.

Artikel ini tersedia dalam: Indonesia · English

Setelah menekan ekspor di Clincoo, file zip bisa terpotong di jaringan lambat atau tersimpan dua kali dengan nama mirip. Tanpa sidik file, kamu mengunggah salinan yang salah ke host baru dan baru sadar saat CSS atau gambar 404.

Hitung checksum SHA-256 di komputer lokal segera setelah unduh selesai. Di macOS atau Linux: shasum -a 256 proyek.zip. Di Windows PowerShell: Get-FileHash proyek.zip -Algorithm SHA256. Tempel hasilnya di README proyek atau catatan rilis.

Sebelum unzip di server atau di folder cadangan, hitung ulang hash. Jika berbeda, unduh ulang dari editor Clincoo. Jangan menambal zip yang rusak dengan menyalin file dari salinan lama: struktur folder dan path relatif mudah tertukar.

Simpan juga tanggal ekspor dan nama branch atau judul proyek di baris yang sama dengan hash. Tim yang pindah host seminggu kemudian tidak perlu menebak zip mana yang "yang terakhir bagus".

Uji zip di folder lokal: buka index.html lewat server statis sederhana, cek favicon, robots, dan aset relatif. Baru unggah. Checksum plus uji lokal lebih murah daripada rollback DNS.
