Use Passive Listeners for Clincoo Touch and Scroll

A touchmove listener that may call preventDefault makes Clincoo scroll feel stuck. Mark it passive if you will not intercept the gesture.

This article is available in: Indonesia · English

A Clincoo page on a phone feels heavy when scripts listen for touchstart or wheel without options. The browser waits to see if preventDefault will run before it scrolls.

In editor.clincoo.buzz, write addEventListener('touchmove', handler, { passive: true }) when the handler only records position or analytics. Scroll can start immediately.

If you must intercept a gesture, such as a carousel that absorbs horizontal swipe, do not use passive. Limit the listener to that element, not document.

Modern browsers treat root touch listeners as passive by default. Do not rely on that; write the option so AI and teammates see the intent.

Test in phone preview: flick-scroll, then swipe a card. If the page hitchs, check DevTools for a non-passive warning.

Scroll performance is an event concern, not only CSS. Clincoo renders the files you save; passive keeps touch smooth on app.clincoo.buzz.
