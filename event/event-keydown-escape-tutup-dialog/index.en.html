Handle Escape keydown to Close a Clincoo Dialog

A Clincoo dialog with only a close icon is hard to dismiss. Listen for Escape on the document while it is open.

This article is available in: Indonesia · English

Clincoo visitors often close overlays with Escape. If the script only listens for a click on the close icon, keyboard and screen-reader users stall.

In editor.clincoo.buzz, attach a keydown listener on document when the dialog opens. Check event.key === 'Escape', then call the same close function as the icon.

Remove the listener as soon as the dialog closes. A leftover global listener will close the next overlay or interrupt input on the next page.

If you use the native dialog element, close() already responds to Escape. Do not double-handle unless the overlay is custom.

Ask AI to paste a separate Escape handler instead of rewriting the whole modal. Test in preview with Tab, then Escape.

The WAI-ARIA dialog pattern requires Escape. Clincoo renders the HTML you save; keyboard events are part of the product, not decoration.
