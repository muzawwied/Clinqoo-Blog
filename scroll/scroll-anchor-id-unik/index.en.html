Use Unique IDs for Scroll Anchors on Clincoo Pages

Two headings with the same id send the link to the first target. Audit ids before you ship a table of contents.

This article is available in: Indonesia · English

A table of contents in a Clincoo template fails when two sections share an id. The browser always jumps to the first element.

Run document.querySelectorAll('[id]') in the editor.clincoo.buzz console. Note duplicate ids, then change the section slug in markup.

Do not start an id with a digit. Avoid spaces. Match link href values to ids on app.clincoo.buzz.

Paste the id list to AI. Do not ask it to fix scroll if the problem is a duplicate id.

Clincoo on blog.clincoo.buzz refers to pages by slug; in-page ids must be unique like those slugs.
