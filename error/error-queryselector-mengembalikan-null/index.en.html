Handle a Null querySelector before Touching Properties in Clincoo

querySelector returns null when the selector is wrong or the script runs too early. Check the result before classList or textContent.

This article is available in: Indonesia · English

The message Uncaught TypeError: Cannot read properties of null in a Clincoo preview almost always comes from document.querySelector(...).classList when the element is missing. One letter in the selector is wrong, the id changed, or the script sits in without defer.

MDN states that querySelector returns an element or null — not an exception. Your job is the branch: const el = document.querySelector('#cta'); if (!el) return; and only then touch properties. Optional chaining el?.classList.add('ready') keeps the tab calm, but still log why so a bad selector does not hide.

Fix order: open the console, copy the selector, paste it in Elements with Ctrl+F. If it does not match, fix the string. If it matches, move the script to the end of body or listen for DOMContentLoaded.

Do not wrap the whole file in an empty try/catch. That hides other errors. Handle null at the query site and leave real failures red.

After the fix, hard-refresh the preview. If the TypeError is gone but the button still does not change, the problem has moved to CSS or a listener — that is progress, not a regression.
