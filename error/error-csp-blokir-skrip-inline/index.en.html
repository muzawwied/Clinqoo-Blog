Read Content-Security-Policy When Clincoo Inline Scripts Are Blocked

The message 'Refused to execute inline script' is not a click bug. Check the CSP header in the Network tab.

This article is available in: Indonesian · English

The preview on editor.clincoo.buzz can stay silent without a stack. Open Console and look for Refused to execute inline script because of Content Security Policy.

Switch to Network, select the HTML document, and read Content-Security-Policy. Note script-src: whether it allows 'unsafe-inline' or a nonce.

onclick attributes and script blocks without a nonce are rejected. Move the logic into an external .js file allowed on the same host.

If inline is required, take the nonce from the server and match the header. Do not add 'unsafe-inline' just to make a demo work.

Retry on app.clincoo.buzz with cache disabled. Paste the full CSP message to AI, not only 'the button does nothing'.
