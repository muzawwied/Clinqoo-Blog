Cek Status HTTP sebelum Menganggap Fetch Clincoo Berhasil

fetch tidak melempar error pada 404 atau 500. Periksa response.ok atau status sebelum parse JSON di proyek Clincoo.

Artikel ini tersedia dalam: Indonesia · English

Di editor Clincoo, banyak formulir dan daftar data memakai fetch. Promise fetch hanya gagal saat jaringan putus. Respons 404, 401, atau 500 tetap masuk cabang then, sehingga JSON.parse atau response.json() membaca halaman error HTML.

Simpan objek Response dulu. Jika !response.ok, tampilkan status dan teks singkat, lalu return. Jangan langsung memanggil json(). Pola ini sama dengan dokumentasi Fetch API: ok adalah singkatan status 200–299.

Bedakan error jaringan dan error aplikasi. Jaringan muncul di catch. Status HTTP muncul setelah Response diterima. Pesan ke pengunjung harus berbeda: coba lagi nanti versus perbaiki isian atau login ulang.

Uji di pratinjau Clincoo dengan URL yang sengaja salah dan dengan endpoint yang mengembalikan 500. Buka tab Network: lihat status, Content-Type, dan body. Jangan mengandalkan konsol saja.

Guard status mencegah satu endpoint rusak merusak seluruh halaman. Setelah status aman, baru parse JSON dan isi DOM. Clincoo tidak menambahkan wrapper fetch untukmu; pemeriksaan ini tetap tugas skrip halaman.
