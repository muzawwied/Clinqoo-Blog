Mark WIP Drafts so Teammates Do Not Deploy Half-Finished Pages

Unmarked drafts look ready to ship. Label files and change notes before a teammate reviews or deploys.

This article is available in: Indonesia · English

In a Clincoo project, a page still in progress often looks complete in preview. A teammate who only sees the render may assume the draft is ready and push it to production.

Mark unfinished work in the file name, an HTML comment, or the handoff summary. A WIP prefix or a "do not deploy" note is cheaper than a rollback after visitors see a broken layout.

In editor.clincoo.buzz, keep a large change in a separate file. Do not overwrite production index.html until preview, contrast, and links are checked.

If you use Git, put WIP in the commit message and do not merge to the main branch yet. GitHub Docs stress that draft status and PR descriptions tell reviewers what is still unsafe to ship.

When the page is ready, remove the WIP marker in the same commit as the last fix. A clean trail keeps Clincoo collaboration auditable a week later.
