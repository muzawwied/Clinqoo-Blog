Revoke Object URLs after Clincoo Upload Previews

URL.createObjectURL keeps the blob in memory. Revoke the old URL when the file changes so the tab does not swell.

This article is available in: Indonesia · English

Local previews in a Clincoo form usually call URL.createObjectURL. Each call leaves a reference that does not go away on its own.

Store the active URL in a variable. When the user picks a new file or clears the preview, call URL.revokeObjectURL before creating the next one.

If you use FileReader.readAsDataURL instead, the blob is not held via an object URL, but the base64 string is heavier in the DOM. Pick one pattern and stick to it.

Also revoke when the page is hidden or the form is reset. A small leak shows up after dozens of upload attempts in one session.

Ask the AI to add revoke in the change and reset handlers only. Do not let it create object URLs inside a loop with no list to clean.
