Limit Image Width and Height before Clincoo Upload

A small file can still be heavy at 6000 pixels. Check naturalWidth and naturalHeight before sending FormData.

This article is available in: Indonesia · English

Byte-size checks are not enough. A 400 KB photo that is 8000 pixels wide still breaks preview and forces a huge canvas in editor.clincoo.buzz.

Create an Image from an Object URL and read naturalWidth and naturalHeight after load. Reject the file if either side exceeds the limit you show in the UI, such as 2400 pixels.

If the image is too large but still usable, offer a client-side resize with canvas or createImageBitmap. Do not upload raw camera resolution to app.clincoo.buzz.

Write an error that names the actual dimensions and the limit so users can crop on their device.

Ask the AI to add only a dimension check on the existing file input. Do not let it overwrite compression or drag-and-drop that already works.

A dimension cap keeps the tab memory low and makes Clincoo galleries feel fast after deploy.
