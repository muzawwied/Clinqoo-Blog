Write Code Comments about Why, Not What

Comments that repeat the function name go stale fast. Record the reason, the constraint, and the decision the code does not show.

This article is available in: Indonesian · English

On editor.clincoo.buzz, a comment that only repeats the next line adds noise when AI and teammates read the diff.

Write the why: an API limit, a product decision, or a bug that already happened. Example: wait 150ms because search input fires a request on every keystroke.

Do not comment what the function name already says. If the name is unclear, fix the name instead of adding a paragraph.

When you ask AI for help, paste the why-comment with the snippet. AI is less likely to delete an intentional constraint.

Delete comments that are no longer true after a refactor. A stale comment is worse than no comment.

Check in the app.clincoo.buzz preview that the behavior described by the comment still matches, then note it on blog.clincoo.buzz if the decision is reused.
