Unstage Clincoo Files with restore, Not reset --hard

reset --hard throws away unsaved work. git restore --staged only drops a file from the commit queue.

Indonesia · English

When preparing a Clincoo commit it is easy to over-add: a .env file, a build artifact, or a CSS experiment lands in staged. A reflex reset --hard also wipes the working tree. That loses copy you never backed up.

The safe unstage command is git restore --staged <file>. File contents stay in the editor; only the index moves back. If you also want to discard working-tree edits, git restore <file> without --staged — still narrower than a hard reset to HEAD.

Make git status and git diff --staged a habit before every commit. If a path does not belong, restore it one by one. Avoid wildcards unless you have read the list.

Use reset --hard only when you accept losing everything dirty. On a Clincoo static site, a newly written hero costs more than one extra command.

Document restore in the team README so new members do not copy old tutorials that still treat reset as a daily tool.
