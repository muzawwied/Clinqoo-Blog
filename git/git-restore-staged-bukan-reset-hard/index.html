Kembalikan File Staging Clincoo dengan restore, Bukan reset --hard

reset --hard membuang kerja yang belum tersimpan. git restore --staged hanya menurunkan file dari antrian commit.

Artikel ini tersedia dalam: Indonesia · English

Saat menyiapkan commit proyek Clincoo, mudah kelebihan add: file .env, hasil build, atau percobaan CSS masuk staged. Refleks reset --hard menghapus juga perubahan di working tree. Itu kehilangan teks yang belum sempat disalin.

Perintah yang aman untuk batal-staging adalah git restore --staged <file>. Isi file tetap di editor; hanya status index yang mundur. Kalau kamu juga ingin membuang suntingan di working tree, git restore <file> tanpa --staged — tetap lebih sempit daripada reset keras ke HEAD.

Biasakan git status dan git diff --staged sebelum commit. Jika ada path yang tidak relevan, restore satu per satu. Jangan biasakan wildcard kecuali kamu benar-benar melihat daftarnya.

reset --hard hanya untuk situasi yang kamu sadari: working tree kotor dan kamu rela kehilangan semuanya. Di situs statis Clincoo, kehilangan hero yang baru ditulis lebih mahal daripada satu perintah ekstra.

Catat perintah restore di README tim agar anggota baru tidak meniru tutorial lama yang masih mengajarkan reset sebagai alat sehari-hari.
