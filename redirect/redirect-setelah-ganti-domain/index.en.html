Redirect an Old Domain to a New Clincoo Domain without Chains

A domain move breaks links and rankings if redirects chain or use the wrong status.

Indonesia · English

When a Clincoo project moves from pages.dev or an old domain to a new host, every public URL needs one hop to its HTTPS counterpart. Google Search Central wants 301 for a permanent move, not 302 which looks temporary.

Do not build a chain from old HTTP to old HTTPS to the new host. MDN notes each hop adds latency and loop risk. Point the old host straight at the new canonical URL, keeping the same path and query.

On the old host keep a rule that preserves the path. /artikel/foo should land on https://new-domain/artikel/foo, not only the homepage. Keep the trailing-slash policy you already chose.

Test with curl -I on home, one article, and 404. Status should be 301 or 308, Location must be HTTPS, and it must not bounce back to the old host. Search Console needs the new property verified before you move the sitemap.

Ask the AI for an old-to-new URL list, not a script that guesses hostnames. After cutover, leave the 301s in place; do not tear them down the next week.

Sources: MDN HTTP redirections, Google Search Central redirects, web.dev load times.
