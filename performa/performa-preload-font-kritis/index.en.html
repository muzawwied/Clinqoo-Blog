Preload Critical Title Fonts on a Clincoo Site

A late title font holds LCP back. Preload one woff2 file that the Clincoo hero actually uses.

This article is available in: Indonesia · English

The hero title is often the LCP element. If the font family downloads after CSS finishes, text first appears in a fallback face and then jumps. In the Clincoo workspace, store one woff2 for the weight used by the title, not the whole family.

Add a preload link in the head of pages that use that title: rel="preload" as="font" type="font/woff2" crossorigin, with href pointing at the file in assets. Without crossorigin the browser may fetch the font twice. Do not preload italic, extra-bold, or files that never appear above the fold.

Pair it with an @font-face that uses font-display: swap and a local src. Preload without a matching @font-face only wastes bandwidth. In the preview Network panel, confirm the font request starts before a large hero image.

After you deploy the Clincoo subdomain, measure again on a phone. If LCP stays on an image, a single font preload is still cheap. If LCP is the title text, the right preload cuts fallback delay.

Remove unused preloads when you change the brand or fall back to system fonts. Stale preloads still count as high-priority resources and can delay CSS.
