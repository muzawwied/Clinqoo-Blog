Set width and height on Clincoo Images so the Layout Does Not Jump

Images without reserved size hurt CLS. Write the intrinsic width and height before you upload to the workspace.

This article is available in: Indonesia · English

Hero and product photos on a Clincoo site often arrive after the text. With no reserved space, headings and buttons slide down when the file finishes loading. A visitor about to tap a CTA hits another link instead.

Set width and height to the file's real pixels. The browser computes the aspect ratio and keeps an empty box. CSS may still use max-width: 100% and height: auto; the ratio from the attributes remains in force.

Do not rely on a guessed min-height alone. A wrong value still causes a jump. Check the file properties before the asset enters the workspace, then paste the same numbers into markup in editor.clincoo.buzz.

Decorative images below the fold may lazy-load, but they still need size attributes. Lazy loading without width and height delays the jump; it does not remove it. Prioritize a hero LCP image that already has a reserved box.

After you ship, open the phone preview and hard-refresh. If text does not shift when the image appears, the attributes are doing their job. A calm page feels faster even when the file weight stays the same.
