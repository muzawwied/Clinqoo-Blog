Separate Pending and Success in the Payment Flow

A visible QR code is not a paid order. A Clincoo page should unlock access only on success, not when the invoice is created.

This article is available in: Indonesia · English

Many store bugs come from one if: the invoice exists, so premium content opens. Pending only means the customer can still pay.

Store three explicit states: created, pending, success. Expired and failed must not collapse into success just because there was no network error.

The download or continue button in app.clincoo.buzz reads the latest status from the server, not a variable set when pay was clicked.

In preview, run the pending path until timeout. Confirm a copied button does not open a paid file before a verified success webhook.

Write a human label: waiting for payment, not a raw status code. Visitors do not need the internal enum name.
