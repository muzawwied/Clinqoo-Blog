Use an Idempotency Key when Creating a Payment Transaction

A double click on pay must not create two invoices. Send the same idempotency key for the same Clincoo order.

This article is available in: Indonesia · English

A slow network makes people press pay again. Without an idempotency key, the Clincoo gateway can create two transactions for one cart.

Create the key once when the order opens, store it on the draft, and resend that same key if the request times out. Do not mint a new UUID on every click.

The server should return the existing transaction when the key matches and the payload is equivalent. If the payload differs, reject with 409 so the amount does not change silently.

Show one UI state: waiting, not two spinners. In the editor.clincoo.buzz preview, test a double click on the button before deploy.

Store the key next to the order id in a short log. That is enough to trace a complaint without copying a card number or token.
