Verify the Webhook Signature before Changing Payment Status

Do not treat a webhook body as trusted. Match the signature and timestamp first, then write a paid status in Clincoo.

This article is available in: Indonesia · English

A payment webhook can be forged if a public endpoint accepts any JSON. In a Clincoo project, store a paid status only after the signature matches a secret that never ships to the page.

Read the signature header and the send time. Reject requests older than a few minutes so an old replay cannot change an order that already finished.

Compare the signature with a constant-time check, not a plain ==. On failure, return 401 and do not touch the balance or status in app.clincoo.buzz.

Log the event id, not the whole body. Repeat the test from the Clincoo payment docs in preview before pointing the endpoint at production.

The editor at editor.clincoo.buzz can paste a verification snippet. Keep the secret in the server environment, not in a file deployed as a static site.
