Record an Interaction in the DevTools Performance Panel before Blaming CSS

A page that feels heavy is not always the images. A Performance recording shows scripts and layout that eat frames.

This article is available in: Indonesia · English

When a Clincoo preview stutters on scroll, people shrink images first. Often the culprit is a script that forces layout on every scroll, not JPEG size.

Open DevTools → Performance. Hit Record, scroll from the hero to the footer, then Stop. Look for long blocks on the Main thread: Evaluate Script, Recalculate Style, and Layout. Function names in the stack point to the file you should trim.

Do not delete an entire stylesheet because one frame is red. Isolate first: disable one scroll listener in editor.clincoo.buzz, record again, compare duration. A fix that does not change the flame chart only adds debt.

Paste a recording snippet or function name to AI, not the sentence "the page is slow". Ask for one change per file. Test the preview again before you export to app.clincoo.buzz.

The Performance panel is evidence, not opinion. One five-second recording saves a night of guessing selectors.
