Filter Console Levels in DevTools when Debugging Clincoo Scripts

console.log mixes with browser noise. Filter Default levels so Clincoo debug, warn, and error lines stay visible.

This article is available in: Indonesian · English

When a Clincoo site preview opens, the console fills with extension noise and third-party warnings. Your script messages disappear.

In Chrome DevTools, open Console and use Default levels. Turn off Verbose if you only need warn and error from the file you edit in editor.clincoo.buzz.

Add a stable prefix such as [clincoo] on log objects. The DevTools Filter box can isolate that prefix without deleting code.

Do not leave production console.log on public pages. Prefer console.debug for development traces so they are easy to silence on the live subdomain.

After a fix, clear the console and reload preview. Remaining logs should be explainable in one sentence.
