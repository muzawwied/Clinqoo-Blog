Separate console.debug, warn, and error in Clincoo Scripts

Routing every message through console.log makes filtering hard. Match the level to the problem.

This article is available in: Indonesia · English

When debugging a Clincoo form, success traces, validation warnings, and network failures often share one console.log. DevTools then cannot hide the noise.

Use console.debug for step traces, console.warn for recoverable input issues, and console.error for flow-breaking failures. Skip alert.

Filter by level in DevTools during preview. On public pages, disable debug or gate it behind an editor-only flag.

Do not log personal data: emails, tokens, or full form bodies. One context object without secrets is safer and easier to export.

Clincoo ships scripts as written. Honest console levels speed fixes without polluting visitor consoles.
