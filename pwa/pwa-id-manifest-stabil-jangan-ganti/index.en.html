Keep the Clincoo PWA Manifest id Stable

Changing the manifest id or start_url makes the browser treat the app as new. Visitors lose the icon they already installed.

This article is available in: Indonesia · English

Once a Clincoo site is installed on the home screen, the browser binds that install to the manifest identity. The id field, or if it is missing the mix of start_url and scope, is that key. Changing the start_url slug for a short rebrand creates a second icon.

Set an explicit id in manifest.json, for example an absolute path you will not move. Change name and short_name when the brand changes. Icons and theme_color may change; the id should not.

Keep scope and start_url aligned with the public folder on the Clincoo subdomain. A scope narrower than start_url opens the app outside the cached area. Check the file in editor.clincoo.buzz before you deploy.

If you must move the path, plan a two-icon period and tell users. Do not trust AI that rewrites the whole manifest on every generate. Review the id field in the diff by hand.

Test the install in Chrome over HTTPS. Remove the old install only on a test device, not on a client device. A stable identity makes the PWA feel like an app instead of a link that keeps changing names.
