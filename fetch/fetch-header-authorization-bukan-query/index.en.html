Send Clincoo Fetch Tokens in the Authorization Header, Not the Query

Tokens in URLs land in server logs, history, and referrers. Use an Authorization Bearer header in Clincoo fetch.

This article is also available in: Indonesia · English

Scripts in editor.clincoo.buzz often stick an API token in the query string for a quick test. That URL is recorded in access logs, CDN caches, and sometimes the Referer header on the next page.

Fetch accepts a headers object. Set Authorization: Bearer plus the token and keep the path clean. Do not hard-code tokens in files that deploy to app.clincoo.buzz.

MDN Fetch docs describe Headers as a map you fill before the request leaves. web.dev treats credentials in the URL as a security anti-pattern.

If a third-party endpoint rejects custom headers because of CORS, solve it with a server proxy instead of moving the secret into the query. Ask AI to add headers without changing the path.

After saving, test in the Clincoo preview: the Network tab should show an Authorization header and a URL without a token. Rotate any token that leaked through a query.
