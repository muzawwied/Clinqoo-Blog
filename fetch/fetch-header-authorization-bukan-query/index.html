Kirim Token Fetch Clincoo di Header Authorization, Bukan Query

Token di URL masuk log server, riwayat, dan referrer. Pakai header Authorization Bearer di fetch Clincoo.

Artikel ini tersedia dalam: Indonesia · English

Skrip di editor.clincoo.buzz sering menempel token API di query string agar cepat tes. URL itu tercatat di access log, cache CDN, dan kadang di header Referer saat halaman berikutnya dimuat.

Fetch mendukung objek headers. Setel Authorization: Bearer plus token, lalu biarkan path tetap bersih. Jangan hard-code token di file yang ikut ter-deploy ke app.clincoo.buzz.

Dokumentasi Fetch MDN menjelaskan Headers sebagai map yang bisa diisi sebelum request berangkat. web.dev menekankan bahwa kredensial di URL adalah anti-pola keamanan.

Jika endpoint pihak ketiga menolak header kustom karena CORS, pecahkan di sisi server proxy, bukan dengan memindahkan rahasia ke query. Minta AI menambahkan headers tanpa mengubah path.

Setelah simpan, uji di pratinjau Clincoo: Network tab harus menampilkan header Authorization dan URL tanpa token. Rotasi token lama yang sempat bocor di query.
