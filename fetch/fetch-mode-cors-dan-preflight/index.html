Pahami Preflight CORS sebelum Fetch Clincoo ke Domain Lain

Header Authorization atau Content-Type JSON memicu OPTIONS. Tanpa Access-Control-Allow-* yang cocok, fetch Clincoo gagal diam-diam.

Artikel ini tersedia dalam: Indonesia · English

Situs yang di-deploy dari Clincoo memanggil API di domain berbeda. Konsol menampilkan blocked by CORS policy meski endpoint hidup saat dibuka di tab baru.

MDN CORS menjelaskan preflight OPTIONS untuk request non-sederhana. Content-Type application/json dan header Authorization hampir selalu memicu preflight.

web.dev merinci header balasan yang wajib: Allow-Origin, Allow-Methods, Allow-Headers. Jangan setel mode no-cors hanya untuk menyembunyikan error; body menjadi opaque dan tidak bisa di-parse.

Di editor.clincoo.buzz, uji dulu GET tanpa header kustom. Jika itu lolos, tambahkan header satu per satu sampai preflight muncul. Perbaiki server atau pakai proxy same-origin.

Clincoo tidak menonaktifkan kebijakan browser. Memahami preflight menghemat jam debugging di app.clincoo.buzz sebelum menuduh fetch rusak.
