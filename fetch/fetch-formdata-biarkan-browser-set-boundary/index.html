Jangan Setel Content-Type Manual saat Fetch Clincoo Mengirim FormData

Browser harus menulis boundary multipart sendiri. Header application/json atau multipart tanpa boundary merusak unggahan.

Artikel ini tersedia dalam: Indonesia · English

Form unggah di situs Clincoo memakai new FormData(form) lalu fetch POST. Jika skrip juga menempel Content-Type: application/json atau multipart/form-data tanpa boundary, server tidak bisa memotong field dan file.

Biarkan browser mengisi header. Objek FormData memicu boundary acak yang cocok dengan body. MDN FormData dan Using Fetch sama-sama memperingatkan agar header itu tidak ditimpa.

Di editor.clincoo.buzz, hapus baris headers Content-Type pada fungsi unggah. Pertahankan credentials jika sesi cookie dibutuhkan.

Uji dengan file kecil di pratinjau. Payload Network harus berjenis multipart dengan boundary, bukan JSON string. Minta AI membedakan cabang JSON versus FormData.

Pola ini menjaga unggahan di app.clincoo.buzz tetap utuh tanpa mengubah backend. Satu header yang salah lebih sering menjadi penyebab gagal upload daripada ukuran file.
