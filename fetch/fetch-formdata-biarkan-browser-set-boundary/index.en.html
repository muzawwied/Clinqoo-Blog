Do Not Set Content-Type Manually When Clincoo Fetch Sends FormData

The browser must write the multipart boundary itself. A JSON or boundary-less multipart header breaks uploads.

This article is also available in: Indonesia · English

Upload forms on a Clincoo site use new FormData(form) then fetch POST. If the script also sets Content-Type to application/json or multipart/form-data without a boundary, the server cannot split fields and files.

Let the browser fill the header. A FormData body triggers a random boundary that matches the payload. MDN FormData and Using Fetch both warn against overwriting that header.

In editor.clincoo.buzz, delete the Content-Type header line on the upload function. Keep credentials if a session cookie is required.

Test with a small file in preview. The Network payload should be multipart with a boundary, not a JSON string. Ask AI to split the JSON branch from the FormData branch.

This pattern keeps uploads on app.clincoo.buzz intact without changing the backend. One wrong header fails uploads more often than file size does.
