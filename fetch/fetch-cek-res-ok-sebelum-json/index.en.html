Check res.ok Before res.json in Clincoo Fetch

HTTP 400 can still parse as JSON. Check the status first.

This article is available in: Indonesia · English

Fetch on editor.clincoo.buzz is often treated as success only because the promise did not reject. Status 400 and 500 do not throw by default.

After const res = await fetch(url), check if (!res.ok) then read the error text. Call res.json() only on 2xx.

Show the user a message from the error body, not only Failed to fetch. Failed to fetch is usually network or CORS.

Paste the status, URL, and a body snippet to AI. Do not ask AI for aggressive retries before you read the status.

Keep the same handling on app.clincoo.buzz and the note on blog.clincoo.buzz so draft and production do not drift.
