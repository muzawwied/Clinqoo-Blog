A Clincoo Fetch Response Body Can Be Read Only Once

response.json() locks the stream. A second text() or json() call throws body already used.

This article is also available in: Indonesia · English

A Clincoo logger calls response.text() for debug, then business code calls response.json(). The second promise rejects because the body is a one-shot stream.

MDN Response documents bodyUsed. After json(), clone() is already too late. Clone before reading if two consumers need the same payload.

In editor.clincoo.buzz, read once into a data constant, then log that copy. Do not reread the Response object.

GitHub docs on fetch in Actions also treat the body as a stream. The same pattern applies in a static Clincoo browser app.

Test both success and error branches. The body already used message disappears when a single parse function becomes the only data source for the UI on app.clincoo.buzz.
