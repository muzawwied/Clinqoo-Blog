Check the Permissions API before Copying to the Clincoo Clipboard

writeText can be denied with no message. Query clipboard-write first so a Clincoo copy button has a clear fallback.

This article is available in: Indonesia · English

A Copy code button on a Clincoo page sometimes stays silent. Visitors think the script is broken, while clipboard-write is denied or still prompting.

Call navigator.permissions.query({name:'clipboard-write'}) when the browser supports it. If the state is not granted, show a select-the-text instruction.

Still wrap navigator.clipboard.writeText in try/catch. A granted permission can fail outside a user gesture.

Do not ask the AI to disable native Ctrl+C. The fallback should add to system behavior, not replace it.

Test on HTTPS at app.clincoo.buzz and in local preview. Permission behavior differs between a secure context and file://.
