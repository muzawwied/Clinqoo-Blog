Find Slow Clincoo Assets with Resource Timing

The Network tab is easy to miss. Resource Timing records each file after the production page loads.

Indonesia · English

After you deploy a Clincoo project, a page can feel slow even when a lab Lighthouse run looks green. The cause is often one font, analytics script, or hero image with a long transfer on the visitor network. The Resource Timing API records startTime, responseEnd, and transferSize per URL without recapturing the Network tab.

Open the production page, then in the console run performance.getEntriesByType("resource"). Sort by duration. Files over 500 ms deserve suspicion: a heavy format, a cache miss, or a cold third-party origin.

Do not measure only in the editor preview. Production CDN and cache differ. Repeat on a phone with 4G throttling so the numbers resemble real visitors.

After you find the URL, fix one asset: compress the image, defer a non-critical script, or preload the font. Measure duration again. Monitoring only helps when it turns into an action, not an ignored list.

Keep a timing snapshot in the release notes. If LCP rises next week, you have an objective baseline instead of a vague feeling that the site is slower.
