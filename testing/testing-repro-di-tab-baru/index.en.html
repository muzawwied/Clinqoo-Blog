Reproduce the Bug in a Fresh Tab Before Writing Clincoo Tests

If the bug does not appear in a clean tab, it is local state, not a code regression.

This article is available in: Indonesia · English

Before writing a test in editor.clincoo.buzz, open the same URL in a private tab. Many bugs are leftover localStorage.

Write the repro steps: URL, clicks, typed data. A good test mirrors those steps, not the test harness.

If it fails in one browser only, paste the User-Agent and console message to AI. Do not ask for a full suite rewrite.

One test per behavior. Do not mix login, upload, and export in one function.

This flow is used when checking the app.clincoo.buzz preview and links on blog.clincoo.buzz.
