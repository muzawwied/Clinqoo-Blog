Do Not Disable Every Lint Rule for One Clincoo Line

A file-wide eslint-disable hides other bugs. Turn off one rule, on one line, with a reason.

This article is available in: Indonesia · English

When editor.clincoo.buzz is red from one no-unused-vars, the temptation is an eslint-disable on the first line. Every warning disappears, including an empty image alt.

Read one error first. Fix the variable name or remove the import. That is faster than turning the rule off.

If the rule is truly wrong there, use eslint-disable-next-line and name the rule. Add a short comment why.

Do not copy the disable into every file. One copied exception becomes a team habit.

When asking AI for help, paste the lint message and 15 lines around it. Ask for a fix, not a comment that disables every rule.

Record remaining exceptions on blog.clincoo.buzz so app.clincoo.buzz does not repeat a global disable.
