Tell an Empty Array from null in Clincoo Payloads

null means the data is missing. An empty array means the list exists and has zero items. Mixing them breaks rendering.

This article is available in: Indonesia · English

In editor.clincoo.buzz, a comment list is sometimes null and sometimes []. Both pass JSON.parse, then code that calls .map crashes only on null.

Agree on a contract: no items means []. Use null only for a field that is truly omitted, then default it in one place.

After parse, check Array.isArray before map. Do not rely on if (data) because an empty array is still truthy and null is not.

When debugging, log the type and length, not the whole payload. Do not paste tokens or user emails to the console.

Ask AI to review one render function, with examples {"items":null} and {"items":[]}. Do not ask AI to rewrite the client.

Keep both payload examples on blog.clincoo.buzz so app.clincoo.buzz does not misread an empty state.
