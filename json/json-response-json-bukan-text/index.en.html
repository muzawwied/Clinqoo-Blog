Use Clincoo response.json(), Do Not Parse Raw Text without Checking Status

fetch().then(r => r.text()) then JSON.parse hides the HTTP status. Use response.json after checking ok.

This article is available in: Indonesia · English

Clincoo pages that call an API often write r.text() then JSON.parse. If the server returns 500 as HTML, parse explodes and the error never mentions status.

In editor.clincoo.buzz, check response.ok first. Then call response.json(). Keep JSON.parse for localStorage strings, not for a fetch Response body.

response.json() still throws when the body is not JSON. Wrap it in try/catch and show status plus a content-type snippet so debug is fast.

Do not ask AI to rewrite every fetch. Paste one loadJson(url) helper that returns an object or null, then replace existing calls.

Clincoo runs the script you save. Fetch that checks status keeps app.clincoo.buzz open when the API is down.
