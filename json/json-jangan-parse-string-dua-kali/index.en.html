Do Not JSON.parse a Clincoo Response Twice

An API that returns a wrapped JSON string becomes a weird object after a second parse. Check typeof before parsing again.

This article is available in: Indonesia · English

On app.clincoo.buzz, some draft responses arrive as a string fetch already parsed. A second JSON.parse throws or yields a nested string.

After response.json(), check typeof data. If it is already an object, do not parse again. If it is a string, parse once inside try.

console.log the type and top-level keys. Escaped quotes usually mean double encoding.

Send a response snippet to AI. Ask for a typeof branch, not a generic parse helper.

Test save on editor.clincoo.buzz. Clincoo does not normalize double JSON.
