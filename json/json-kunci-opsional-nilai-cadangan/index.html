Baca Kunci JSON Opsional Clincoo dengan Nilai Cadangan, Jangan Asumsi Selalu Ada

Parse sukses bukan jaminan setiap field ada. Ambil kunci opsional lewat cadangan agar UI tidak menampilkan undefined.

Artikel ini tersedia dalam: Indonesia · English

API dan berkas data.json di proyek Clincoo sering menambah field baru secara bertahap. Kode yang langsung menulis data.author.email akan pecah jika author belum dikirim. JSON.parse berhasil, tapi bentuk objek tidak lengkap.

Setelah parse dan cek tipe objek, baca kunci opsional dengan cadangan yang kamu pilih: const nama = (obj && typeof obj.nama === 'string') ? obj.nama : 'Tanpa nama'. Jangan mengandalkan || semata jika nilai sah bisa 0 atau string kosong.

Untuk objek bersarang, naik bertahap. Cek obj.author dulu, baru obj.author.email. Optional chaining (obj.author?.email) membantu, tetap sediakan string cadangan sebelum menempel ke DOM.

Jangan tampilkan kata undefined atau null di halaman. Pengunjung mengira situs rusak. Nilai cadangan yang manusiawi lebih baik daripada memaksa field yang API belum jamin.

Dokumentasikan kontrak: field wajib versus opsional. Kalau kamu yang menulis JSON, lebih baik kirim null eksplisit daripada menghapus kunci, supaya pembaca tahu field itu memang kosong, bukan terlupa.

Uji dengan tiga payload di pratinjau Clincoo: lengkap, tanpa kunci opsional, dan kunci bernilai null. Ketiganya harus merender tanpa error konsol.
