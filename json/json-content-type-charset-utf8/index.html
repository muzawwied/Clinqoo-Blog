Kirim JSON Clincoo dengan Content-Type application/json; charset=utf-8

Body JSON tanpa header yang benar sering ditolak atau terparse sebagai teks. Tetapkan Content-Type saat fetch dan saat menyimpan berkas.

Artikel ini tersedia dalam: Indonesia · English

Banyak formulir Clincoo mengirim objek lewat fetch tanpa header. Server melihat text/plain, menolak body, atau menyimpan string yang tidak bisa di-parse. Di sisi unduhan, berkas .json tanpa charset merusak tanda kutip pintar dan nama beraksen.

Saat POST atau PUT, set headers: { 'Content-Type': 'application/json; charset=utf-8' } dan body: JSON.stringify(payload). Jangan mencampur FormData dengan stringify. Satu permintaan, satu format.

Saat membaca respons, cek status ok lalu content-type mengandung json sebelum response.json(). Halaman error HTML yang dipaksa parse memunculkan SyntaxError yang tidak ada hubungannya dengan field formulir.

Jika kamu menyimpan data statis di repo — daftar harga, salinan UI — simpan sebagai .json valid, UTF-8 tanpa BOM, tanpa trailing comma. Editor Clincoo menampilkan teks; ia tidak memperbaiki header HTTP saat berkas di-serve.

Uji dengan Network di DevTools: lihat request header dan preview body. Kalau Content-Type masih text/plain, perbaiki fetch sebelum menambah field baru. Catatan satu baris di skrip menghemat debugging webhook.
