Send Clincoo JSON with Content-Type application/json; charset=utf-8

A JSON body without the right header is often rejected or parsed as text. Set Content-Type on fetch and when you store files.

This article is available in: Indonesia · English

Many Clincoo forms send an object with fetch and no headers. The server sees text/plain, rejects the body, or stores a string that cannot be parsed. On download, a .json file without charset breaks smart quotes and accented names.

On POST or PUT, set headers to application/json; charset=utf-8 and body to JSON.stringify(payload). Do not mix FormData with stringify. One request, one format.

When reading a response, check ok and that the content-type contains json before calling response.json(). Forcing parse on an HTML error page yields a SyntaxError that has nothing to do with form fields.

If you keep static data in the repo — price lists, UI copy — save valid .json, UTF-8 without BOM, no trailing comma. The Clincoo editor shows text; it does not fix HTTP headers when the file is served.

Test with Network in DevTools: inspect the request header and body preview. If Content-Type is still text/plain, fix fetch before adding more fields. One line in the script saves webhook debugging.
