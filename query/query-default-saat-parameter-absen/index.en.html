Set Clincoo Query Defaults When a Parameter Is Missing, Do Not Treat Empty as Absent

get() returns null when a key is missing. Distinguish absent, empty, and default so filters do not drift.

This article is available in: Indonesia · English

`params.get('page')` returns `null` if the key is missing, and an empty string if the key exists with no value. Many Clincoo scripts write `page || 1`, which collapses both cases and hides visitor intent.

Write a helper: if `get` is null, use the default; if the string is empty, decide on purpose whether that means reset or page one. Do not rely on truthiness alone.

For numbers, parse after the null check. `Number('')` is 0, which can pass page validation even though the visitor chose nothing.

Test three URLs in preview: no `page`, `page=`, and `page=2`. All three should match the behavior you documented, not a guess.

Ask the AI to add one query-reading helper plus a mental test for those three cases. Do not let defaults scatter across five files.
