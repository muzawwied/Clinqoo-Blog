Check Clincoo Query Keys with has(), Do Not Rely on get() Alone

get() returns an empty string when a key exists without a value. has() distinguishes a missing key from an empty one.

This article is available in: Indonesia · English

Many Clincoo scripts use params.get('sort') || 'baru'. If the URL contains ?sort= with no value, get() yields an empty string and the fallback does not run as you expect.

In editor.clincoo.buzz, call params.has('sort') first. has() is true when the key exists, even if its value is empty. Only then apply a default.

Practical flow: if has('sort') is false, use the project default. If true, read get('sort') and validate against an allowlist. Do not accept arbitrary visitor strings.

Ask AI to replace only the query reader. Paste the has/get helper, not the whole router. Test three URLs: missing key, empty key, and a real value.

Filters on app.clincoo.buzz must be shareable. Distinguishing has() from get() keeps filter links predictable after deploy.
