Sort Clincoo Query Keys Stably So Shared Links Compare Equal

Random key order makes identical filters look different. Sort keys before writing the URL.

This article is available in: Indonesia · English

`?sort=new&tag=css` and `?tag=css&sort=new` render the same page, but logs, sitemaps, and string compares treat them as different. On Clincoo sites that share filter links, random order breaks analytics.

Before `toString()`, copy pairs into an array, sort by key name, then build a fresh `URLSearchParams`. Do not rely on plain-object insertion order if you assemble the query from several sources.

Keep the canonical order in one function. Every filter control and every share link should call that function instead of concatenating strings in place.

Test two different click paths in preview. The final URL must match character for character. If it differs, a branch skipped the sorter.

Ask the AI to tidy only the query serializer. Do not let it rewrite filter logic or card markup.
