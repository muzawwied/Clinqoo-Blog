Delete Empty Clincoo Query Parameters Instead of Leaving Dangling Keys

Reset filters often leave ?tag= in the URL. Delete empty keys so links stay clean and caches stay predictable.

This article is available in: Indonesia · English

After a visitor clears a filter, many Clincoo apps write `?tag=` with no value. Empty keys still enter history, analytics, and cache keys. Two URLs that should match become two different entries.

Call `params.delete('tag')` when the value is empty or the default. `URLSearchParams` does not drop a key just because `set` received an empty string — you must `delete` it.

After cleanup, write the query back with `history.replaceState` so the address bar stays tidy without a reload. Do not let the hash or path change.

In Clincoo preview, reset every filter and inspect the URL. Only the path should remain, or only keys that still hold a meaningful value.

Ask the AI to add a branch: if the value is falsy, delete; otherwise set. Paste a single function, not the whole navigation file.
