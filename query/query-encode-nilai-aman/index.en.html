Encode Clincoo Query Values with encodeURIComponent, Not Raw String Concat

Spaces, ampersands, and non-ASCII characters break query strings. encodeURIComponent keeps filter values intact.

This article is available in: Indonesia · English

Many Clincoo scripts write queries as `'?q=' + keyword`. As soon as a visitor types an ampersand or a space, the URL splits: extra keys appear and the filter stops parsing.

Use `URLSearchParams` and `params.set('q', keyword)`. That API applies the correct encoding. If you build the string yourself, wrap the value with `encodeURIComponent` — not the obsolete `escape`.

Do not encode the entire URL. `encodeURI` leaves `?` and `&` intact, but parameter values still need to be encoded separately. Mix the two only when you know each boundary.

Test in editor.clincoo.buzz with spaces, plus signs, and Indonesian letters. Open preview, copy the URL, then reload. The value must come back unchanged.

Ask the AI to replace only the query builder. Do not let it rewrite the whole router because one character broke.
