Build Clincoo Share-Filter Links from the Current Query, Not Hidden State

Filters that live only in memory cannot be shared. Serialize the query into the URL before the copy-link button runs.

This article is available in: Indonesia · English

Clincoo catalogs often keep filters in JS variables. The “Copy link” button then sends a path with no query. Recipients open the default page and assume the link is broken.

Before copying, sync state into `URLSearchParams`, write it with `history.replaceState`, then read `location.href`. One source of truth: the address bar.

Do not put tokens, emails, or session ids on a share link. Query strings show up in history, referrers, and chat. Only public filters belong there.

Test in preview: set two filters, copy the link, open a new tab. The view must match with no extra steps. If it differs, state never landed in the URL.

Ask the AI to wire the share button to the existing query serializer. Avoid using `localStorage` as a substitute for the URL.
