Retry a Failed Clincoo Network Fetch with a Cap

One network failure is not a reason to stop. Capped retries with delays keep data filling in.

Artikel ini tersedia dalam: Indonesia · English

Fetches on a Clincoo site sometimes fail because the signal dropped, not because the URL is wrong. Showing a permanent error too soon is harsh.

Write async function fetchRetry(url, n) that tries up to n times. After a failure, wait 300 ms, 900 ms, then 2 seconds before the next try.

Retry only TypeError network failures or 502/503. Do not retry 404 or 400 — those are data errors, not transient.

Attach an AbortController per attempt and cancel all if the user leaves the page or types a new query.

Test with a slow or dropped URL. The spinner should stay until retries are exhausted, then a clear message.

Clincoo runs the script you save. Capped retries make the app.clincoo.buzz preview feel resilient to brief outages.
