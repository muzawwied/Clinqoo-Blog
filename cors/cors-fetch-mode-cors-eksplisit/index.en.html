Set Fetch mode cors Explicitly for Clincoo Requests

mode no-cors hides the body and status. Use mode cors when you need to read JSON.

This article is available in: Indonesia · English

A fetch to the API from editor.clincoo.buzz with mode: 'no-cors' yields an opaque response. JSON.parse fails quietly.

Use mode: 'cors' (the default for cross-origin URLs you control) and check res.ok before res.json().

If preflight fails, fix server headers. Do not switch to no-cors just so the Promise resolves.

Test on app.clincoo.buzz and paste the status plus headers to AI. Record the steps on blog.clincoo.buzz.
